## 0. 授权、边界与红线摘要

### 0.1 三条总原则

1. **诊断面从轻，交付面从重**：诊断（免注册问卷 → 异步报告）不继承 G3 门禁/证据那套交付纪律；转正式交付时才进入重流程。
2. **报告即方案底稿**：诊断输出必须能直接衔接 `delivery_plans` / 方案骨架 / 报价，否则退回"通用 AI 出报告"的 commoditized 区间（无差异化）。
3. **北极星不是报告份数**，是「报告 → 认领 → 正式调研/报价」转化率（报告是 MQL 不是商机，行业基准 MQL→SQL ≈ 13%）。

## 8. 完成定义（DoD）

一个单元标 DONE 须同时满足：

1. **产物落位**（真相层或仓库，见 §5 表），且**红线自查表**逐条过；
2. **仓库侧**：文档（本文档 §1 状态列 + CHANGELOG 节）+ 台账回写；
3. **代码侧**（涉 T-06 以后）：新增静态钉须有变异验证记录（红→还原→绿）；结构口径变动则三份审计清单同步重生成（`docs/audit/v3-route-inventory.csv` 等）；
4. **涉桌面**：重打包便携版 + asar 字节验证；
5. **涉服务端**：合并后 rebuild 三镜像 + `alembic upgrade head`；
6. **PR 门**：push fork → PR → 4 个 CI job 全绿（desktop / server-tests / secrets-scan / pseudonymization）→ 合并 → ff 本地 main → 删分支。
