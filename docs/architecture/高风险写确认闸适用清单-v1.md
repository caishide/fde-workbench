# 高风险写密码确认闸适用清单 v1

> CR-064 拍板留痕（2026-11-10 蔡工批准「成文豁免清单」）：平台「高风险写＝admin 门＋当前账号密码二次确认」的适用面与**有意豁免面**自此单点成文；后续新增写路由按本清单归类，豁免面调整须修订本文档并留痕。

## 一、适用面（必须有 confirm_password + 服务层 _confirm_password 配对）

| 域 | 面 | 依据 |
|---|---|---|
| commercial | admin_routes.py 全部写路由（权益/席位/认证/陪跑/扣费方式/记账/配置位/分成登记/企业确认等 21 条） | ADR-007 关键流转默认人工确认；资金/权益敏感 |
| solutions | 交付方案发布（service.py signoff 区） | 对外交付物 |
| control/ai | api_actions.decide_action（AI 代办的密码确认流） | AI 确认闸 |
| extensions | Skill publish/rollback | 平台能力治理 |

配套（CR-047，夜审 r2 落地）：全部确认面共享 `auth/confirm_throttle` 失败限流（5 次/15 分钟，同 key 同阈值同窗口）。

## 二、有意豁免面（不加第二因子；豁免理由留痕）

| 域 | 面 | 豁免理由 |
|---|---|---|
| users | 角色变更/停用/重置密码（users/routes.py） | admin 门＋operation_events 逐动作审计（actor 归因，CR-042 后含 user_password_reset/user_password_changed 事件）；管理频率高，第二因子显著拖慢日常管理且被劫持会话已有 15 分钟 access token 窗口约束＋CR-047 同族限流可后续追加 |
| dispatch | 派单规则版本发布/激活（admin_routes.py） | 同上：admin 门＋事件留痕；规则数值变更可经事件链回滚追溯 |
