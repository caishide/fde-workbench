# 获客诊断工具立项评估 v1

- **状态**：PROPOSED（立项评估 ≠ 实施授权；实施须蔡工拍板后另开轮，走常规闸）
- **日期**：2026-11-10
- **来源**：蔡工提出「免注册企业诊断 / 售前访谈生成问题报告与解决方案」获客设想，goal 会话完成市场研究与能力映射后落盘
- **关联**：商业化 G1–G6（entitlements R1–R4 / 席位 / 结算 / 区域 / 企业空间，2026-11-10 §16 收口 18/18）；fde18 宣传网站（fde-ops 仓）；V3.1 P0-1 discovery 管线；V3.1 P0-3 delivery_plans；T-A2 脱敏三道防线；transcripts 草稿区隔离先例（tb1）

## 1. 一句话立项

把已建成的售前管线（调研表 → 事实抽取 → 方案骨架）对外开一个「**免注册企业诊断**」门脸，作为商业化漏斗的获客顶（top-of-funnel）：

企业自填诊断问卷 → **摘要即时免费**（免注册）→ **完整报告留资解锁** → 创业者（R2）/ 区域合作商（R4）在线索池认领 → 转正式 presurvey/项目 → 报价 → 交付。

配套的第二入口（半公开）：售前创业者替客户填写访谈/调研，生成问题报告与方案建议——该路径工作台内已有约 80%，本立项主要补公开自诊面与线索回环。

## 2. 背景与动机

- 商业化 G1–G6 已把「报价 → 收款 → 合同 → 交付包 → 结算 → 区域 → 企业空间」全链闭环，但**漏斗顶（获客）为空**：R2/R4 没有系统化的线索来源，商业机器缺原料。
- 售前管线服务端已建成约 80%（§4 映射），缺的是**公开匿名面 + 线索模型 + 报告外发形态**，不是诊断能力本体。
- 市场证据（§3）显示「免费诊断获客」是被政府财政与企业行为双侧验证的成熟模式。

## 3. 市场研究证据

> 快照日期：**2026-11-10**。来源为公开网页，仅引事实与抽象结论；按红线第 8 条④，引用前登记出处与快照日期，远端变动/停更超 30 天须复核。不复制任何第三方结构化表达（红线第 8 条）。

### 3.1 政策侧——需求被公共财政验证（最强信号）

- 深圳每年投入 **1 亿元**为企业提供数字化转型免费诊断服务（[深圳市政府](https://www.sz.gov.cn/cn/xxgk/zfxxgj/zwdt/content/post_12712426.html)）
- 辽宁以政府购买服务方式，免费为全省规上工业企业出数字化诊断报告（[辽宁省政府](https://www.ln.gov.cn/web/zwgkx/zfwj/szfwj/2026n/2026061616413753311/index.shtml)）
- 广州为拟改造中小企业提供免费诊断咨询（[广州市工信局](https://gxj.gz.gov.cn/yw/zchb/zcwj/cyzc/content/post_10755592.html)）；常州「智改数转网联」三年行动计划规范诊断服务（[常州市政府](https://www.changzhou.gov.cn/gi_news/522177829389628)）；澳门 2025 中小企业数字化支援含业务诊断与免费方案（[澳门经科局](https://www.gov.mo/zh-hans/news/867307)）
- 工信部背景的国家级数字化转型促进中心已上线「AI 智能诊断 + 供需匹配 + AI 陪跑」，直指中小企业「不愿转、不会转、不敢转」（[ndtpc.com](https://www.ndtpc.com)）

**推论**：①「企业不知道自己的问题在哪」是公认痛点，政府把它当公共服务在买，需求真实且有预算背书；②官方免费诊断会使「纯出报告」快速 commodity 化——报告必须比官方模板更**可落地**；③地方诊断服务采购存在入围资质通道（批量获客 + 背书），列为拍板项 D-4。

### 3.2 漏斗基准——诊断是转化率最高的 B2B 钩子之一

- 互动式测评/计算器类 lead magnet 转化约 **20–30%**，静态 PDF 报告约 5–10%（约 2.4× 差距）；B2B 落地页均值约 2.9%（[Digital Applied 2026 基准](https://www.digitalapplied.com/blog/lead-magnet-conversion-benchmarks-2026-b2b-data-reference)、[Vida.io](https://www.vida.io/blog/best-b2b-lead-magnets)、[SalesHive](https://saleshive.com/blog/b2b-lead-benchmarks-digital-marketing-gen)）
- 设计良好的问卷漏斗完成率 **60–80%**；失败主因 = 题目过多、过早索要联系方式、只求数量不求质量（[QuizLanding](https://www.quizlanding.com/blog/quiz-funnel-metrics)、[GrowthLens](https://www.growthlens.io/blog/quiz-funnel-completion-rate-optimization)、[LanderLab](https://www.landerlab.io/blog/quiz-funnel-questions)）
- 心理机制是互惠（Cialdini）：先给真价值（分数/对标/个性化诊断），再开口要联系方式（[Digioh](https://www.digioh.com/blog/lead-generation-quiz)）

**推论**：「摘要免注册即时可见、完整报告留资解锁」的顺序有实证支持；问卷控制在 10 分钟、30 题以内；逐题流失率要埋点。

### 3.3 竞品侧——模式已验证，存在两个空位

- **康伴科技 COMPAI**：免费快诊 30 分钟（获客钩子）→ ¥4,980/次基础诊断 → 深度诊断。「免费体检获客 + 付费深度变现」已跑通（[compai.cloud](https://www.compai.cloud)）
- **尚贤 SunShare**：五域快速测评 AI 自动出报告、国标成熟度对标、政策补贴测算；测评引流 → 咨询/落地服务（[诊断页](https://www.sunshare.cc/service/diagnose)）
- **Manus 等通用 Agent 工具**可自动收集信号并生成战略报告——通用 AI 对「纯报告生成」构成降维竞争
- **空位①**：「诊断 → 实施方案 → 报价 → 交付」打通——竞品停在报告 PDF
- **空位②**：「卖给售前创业者/咨询师的报告生成 + 获客工具」——恰好对应本仓 R2 创业者 + R4 区域合作商的位置，中国市场搜索未见成熟玩家

### 3.4 判定

需求大、模式成立、赛道有玩家——**不是「想到就赢」，而是「谁把诊断焊进交付闭环谁赢」**。本仓恰有全链交付闭环（G1–G6 + P0-3 + 交付包），这是结构性差异点。

## 4. 与本仓能力映射

| 诊断工具所需能力 | 仓库现状 | 缺口 |
|---|---|---|
| 售前创业者填访谈/调研 | ✅ 调研表引擎：动态字段定义 + 条件显隐 + 三态流转 + 版本化（`research/form_service.py`、T-A3） | 一份对外「诊断问卷定义」 |
| 访谈 → 结构化问题 | ✅ discovery 四表：事实抽取（十值分类）→ 需求（R-key + 结构化验收）→ 强制待澄清（P0-1） | 抽取提示词的「诊断语域」变体 |
| 生成解决方案 | ✅ delivery_plans 确定性生成 + 任务分解（P0-3）+ T-A5 方案骨架模板 | 报告化包装（评分摘要/问题清单/机会建议三层） |
| 企业名/敏感信息处理 | ✅ T-A2 三道防线 + `enterprise_dict` fail-closed | 延伸到报告外发面 |
| AI 成本与审计 | ✅ `execute_ai_prompt` 单一入口 + 月度 token 预算 + purpose 强制（N2） | 匿名会话的配额粒度 |
| 报告之后的商业链 | ✅ 报价→收款→合同→交付包→结算→陪跑/培训→企业空间（G1–G6） | — |
| 分销网络 | ✅ R2 创业者 + R4 区域合作商（G5）+ R1 企业空间（G6） | **线索认领回环** |
| 获客门面 | ✅ fde18 宣传网站已上线（fde-ops 仓） | 诊断入口 + 报告分享页 |
| **公开匿名入口** | ❌ 全部 440+ 路由在 JWT/静态令牌之后 | **NEW `diagnostics/` 匿名面**（最大一块新地） |
| **线索模型** | ❌ 线索 ≠ 项目，不可塞进 projects | `lead_diagnostic_sessions`（零外键指向 projects） |

**关键设计判断**：诊断面**不继承** G3 门禁/证据那套交付纪律——那是 FDE 内部交付重流程；诊断面从轻（10 分钟问卷 → 异步出报告），转正式交付时才进入重流程。

## 5. 差异化主张

1. **报告即方案底稿**：诊断输出直接衔接 delivery_plans / 方案骨架 / 报价（P0-3 + T-A5 + G1），竞品停在报告。
2. **分销网络独有**：R2 创业者认领 + R4 区域合作商专属链接与分润（G5），报告工具型竞品没有销售网络。
3. **方法论背书**：G1–G9 门禁 + 调研表结构 + business_facts 十值分类学——报告有结构化方法论，而非通用 LLM 输出。

## 6. 诚实的风险面（「大火」不是功能的自动结果）

| 约束 | 现实 | 对策 |
|---|---|---|
| 分发真空 | 上线 0 流量，功能再好没人填 | 上线必须绑 1–2 个渠道（§11 Phase 3），否则是无人填写的表单 |
| 报告同质化 | 企业先问「这和问 ChatGPT 有何区别」 | 结构化问卷 + 行业/规模基准对标 + 三层输出，报告结构上像方法论 |
| 免费预期 | 免费报告培养白嫖预期，反噬付费 | 免注册只给摘要（分数+前 3 问题），完整报告留资解锁 |
| 成本与滥用 | 每份报告烧 token；公开免费面 = 刷子目标 | 每 IP/每日上限、匿名 token 预算、异步生成、fail-closed |
| 合规 | 个保法：明示同意 + 隐私政策 + 留存期 | 留资页放隐私政策；报告外发面延续 T-A2 脱敏 |

**期望管理**：诊断报告是 **MQL 不是商机**（行业基准 MQL→SQL 约 13%，[SalesHive](https://saleshive.com/blog/b2b-lead-benchmarks-digital-marketing-gen)）。北极星指标不是「报告份数」，而是「**报告 → 认领 → 正式调研/报价**」转化率。

## 7. MVP 范围提案（一个 PR 量级；实施须另开轮）

### 7.1 服务端 NEW `diagnostics/` 域

- `lead_diagnostic_sessions`：匿名 token / answers JSON / 三层报告 JSON / lead 联系方式（可空）/ status（draft → submitted → report_ready → claimed | expired）/ claimed_by_user_id / created_ip_hash。**零外键指向 projects**（沿用 tb1 transcripts 草稿区「全库零外键指向草稿表」同款隔离手法；认领 = 显式转化动作 + 代号化，不自动写交付真相层）
- 固定诊断问卷定义：≤30 题、条件显隐（复用调研表字段引擎的抽象，不复用其项目绑定）
- AI 报告生成：`execute_ai_prompt` 单一入口 + 预算闸 + purpose 登记（AST 钉白名单需扩登记）+ discovery 抽取提示词语域变体；输出三层（评分摘要 / 问题清单 / 机会与建议）
- 闸：每 IP 每日上限、匿名会话 token 配额、**异步生成**（排队而非同步阻塞）、词典故障 fail-closed 同码
- 留资闸：摘要免注册即时可见；完整报告 = 提交联系方式 + 隐私政策同意
- 报告只读页 share token（分享卡病毒环）

### 7.2 桌面端

- 线索池控制台：R2/R4 按区域可见线索，认领 → 一键转 presurvey 项目（走代号化），canManage 显隐同构

### 7.3 不做什么（负结论）

- 不做注册/账号体系改造（匿名会话即可）
- 不动 projects/users 现有表（线索独立建域）
- 不做实时同步报告（异步 + 上限）
- 不继承 G3 门禁/证据重流程（交付纪律从转化点才开始）
- 不做通用「报告生成器」产品化（那是 Manus 的战场，不差异化）

## 8. 部署形态建议（拍板项 D-3）

**推荐：独立轻部署**——独立 compose + 独立库 + 独立域名（或 fde18 子路径反代），与工作台真相层物理隔离；线索认领走导出/代号化。理由：现役活库为单机自用部署（Windows 宿主 + WSL Docker），公网匿名写口直接开在真相层库上 = 爆炸半径不可接受；诊断面被刷/故障不应影响交付主业务。

备选：①现有栈加匿名路由 + 独立 schema（省一台机器，需重审安全面）；②静态网站 + 云函数（最轻，但脱离 Flask/PG 栈，管线复用成本高）。

## 9. 红线与合规对照

- **客户真实资料红线的边界**：诊断填写 = 企业**自愿自填**的线索数据（有明示同意 + 隐私政策 + 留存期），区别于交付客户的真相层资料（扫描件/凭证不入库纪律不变）；线索表同样指针化 + 脱敏，报告外发面延续 T-A2 `enterprise_dict` fail-closed
- 个保法：留资页明示用途（出报告 + 可能的跟进联系）、提供删除请求通道
- 门禁/证据/AI 审查红线不涉及（本工具不产生交付证据、不执行被审代码）
- 第三方材料：本文档只引公开事实与抽象结论并附来源与快照日期，不复制竞品结构化表达（红线第 8 条）

## 10. 待拍板项（显式不代决）

- **D-1 MVP 首发入口**：推荐 = 企业免注册自诊（创业者代填版工作台内已有 80%）；备选 = 创业者代填先行（风险低但无公开获客面）/ 双入口同发（范围最大）
- **D-2 留资策略**：推荐 = 摘要免费 + 完整报告留资；备选 = 全免注册（拿不到线索，不可跟进）/ 全留资（完成率崩，违背互惠顺序）
- **D-3 部署形态**：推荐 = 独立轻部署（§8）
- **D-4 是否申请地方数字化诊断服务商入围资质**：业务动作非代码，需线下拍板；深圳/广州模式 = 批量获客 + 背书
- **D-5 报告收费梯度**（康伴式：免费摘要 → ¥x 深度诊断 → 交付合同）：挂账到 MVP 验证后

## 11. 推进顺序

1. **Phase 0 人工门房试点（零代码，本周可做）**：用现有 presurvey + discovery 管线人工出 5–10 份诊断报告（半人工即可），验证「报告值不值一个联系方式」与企业看完最想买什么。somwyn 试点已证明管线能跑，缺的只是报告话术。
2. **Phase 1 MVP（§7，D-1~D-3 拍板后另开实施轮）**：服务端 `diagnostics/` 域 + 桌面线索池。
3. **Phase 2 门面接线**：fde18 挂诊断入口 + 报告分享页。
4. **Phase 3 渠道（决定生死）**：D-4 资质申请 / R4 专属诊断链接 / 匿名化报告复盘做内容与短视频素材 / D-5 收费梯度。

## 12. 拍板记录（2026-11-10 party 评审会，留痕可推翻）

- **P-1 主叙事定案**：对外入口叫「**政策补贴测算**」，诊断挂在测算之后（Wildcard 框架采纳）。首屏 3–5 题出「测算结果」（纯规则即时免费，不烧 AI），再续 30 题诊断问卷。引用纪律沿 `knowledge/policy/政策弹药库` 既有红线：只引政策原文口径，「我方解读」必须标注。
- **P-2 售前业务费归属＝先落结构不落数**：三档归因制（渠道报备档 / 平台线索认领档 / 平台留存档）+ **90 天认领窗口制**（沿 leads.md 既有报备制先例）；归因数据由诊断工具自动落（source_type + 渠道链接 ID），零手工记账；20% 为蔡工口头工作数字，**具体比例挂账到价格轮**（G3 先例：分成比例只落结构不落数）。售前业务费属**线索侧名目**，归 G3 收入科目层，与四席位交付分成（`settlements.py` platform/region/city/delivery）分两层，不混算。
- **P-3 线索模型对接既有台账**：诊断线索认领后生成 `L-YYYYMMDD-NN` 线索号写入本地 `leads.md` 台账（九字段 + 9 态 + 回访触发日），**不建平行 CRM**；`lead_diagnostic_sessions` 表只需带 `source_type`/`claim_window_*` 字段，认领动作出台账行。
- **P-4 Phase 0 案例选定**（本地真相层作业，产出代号化）：①somwyn（P0-1 已有 240 事实+74 需求，改写为报告格式最快）；②qiflow（跑一遍 presurvey/discovery 产第二份）；③FDE案例100 取 1–2 个公开案例做校准样本（仅内部测试，不外发派生物——红线第 8 条）。
- **P-5 漏斗五级深挖结论**：见 2026-11-10 评审会纪要——测算卡即时（同步规则）/摘要轻 AI/完整报告异步 AI（异步投递＝天然留资理由）；微信渠道作为邮件之外的送达面；认领 SLA 24h。
