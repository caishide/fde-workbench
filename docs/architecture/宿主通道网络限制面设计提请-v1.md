# 宿主通道网络限制面设计提请 v1（2026-11-10）

> **状态：已实施（2026-11-11，蔡工拍板采纳推荐后随轮落地——以 **A′ 形态**，见文末 §6 实施记录；本节原 PROPOSED 声明留档）**。对应任务书 §9 安全前置 **⑦「网络默认受限，按域名白名单开放」**（§6.1 已随本轮改判已过）。全我方独立设计，零第三方材料引用（红线第 8 条履行）。

## 1. 背景与现状（现测锚）

- 宿主通道＝**宿主 Windows 裸跑态 spawn**（T-Z1 裁定 A）：`host_channel.py` 直接 spawn 宿主 `ZCode.exe`，进程走**宿主自身网络与登录态**（GLM Token Plan 账号）。
- 容器沙箱的 `network_mode: none` 限制面**不适用**（进程不在容器内）⇒ 代码级网络限制面为零：zcode 可访问宿主可达的任意网络端点。
- 当前风险承担方式（§6.1 ⑦处置）：最小工作区＋代号化上下文＋单订单单任务＋零凭据注入（`credentials={}`）——**缓解但不构成限制面**。
- 实测：重跑三（run `bef48e56`）宿主通道全链 completed；产物与工作区留痕可审计，但**网络出口无代码级约束**。

## 2. 目标与非目标

**目标**：为宿主通道 spawn 的 zcode 进程加**代码级出站限制**——默认拒绝、白名单放行（模型 API 端点等必要域）、出口可审计。

**非目标**：
- 不动容器沙箱通道（已有 `network_mode: none`＋DPI 无关）；
- 不做域名级 DPI／TLS 检查（过度工程）;
- 不改变宿主通道五边界（红线第 5 条）与 12 条前置其余各项；
- 本文档不实施——实施须蔡工拍板方案后另立工程轮。

## 3. 候选方案（Windows 宿主现实约束下的四选）

### 方案 A：本地正向代理白名单闸（推荐）

宿主起一个**仅监听 127.0.0.1** 的最小正向代理（我方代码，新增 `agents/host_egress_proxy.py`）：白名单＝模型 API 域名（GLM/MiniMax 端点）＋供应商必要域；spawn zcode 时注入 `HTTPS_PROXY/HTTP_PROXY` 环境变量指向该代理；代理对非白名单出口**拒绝并留审计日志**（域名+时间+run_id 关联）。

- **优点**：纯用户态零驱动；白名单/日志在我方代码与库内可版本管理、可审计；与 zcode 无侵入；实现量小（Python stdlib 可承载，或复用现有依赖）。
- **缺点/前置**：**依赖 zcode 网络栈尊重代理环境变量**——须先做一次最小实测（zcode 请求是否走 `HTTPS_PROXY`）；不走则退方案 B。
- 审计落点：代理拒绝/放行日志→`operation_events`（同构既有事件账），**只记域名不记内容**。

### 方案 B：Windows 防火墙按进程出站规则（兜底）

为 `ZCode.exe` 建出站白名单规则（仅允许模型 API 远端）。

- **优点**：OS 级强制，不依赖应用行为。
- **缺点**：规则维护在 OS 层（版本管理/审计弱、换机迁移清单须加项）；变更须 admin；按 FQDN 集的防火墙规则在 Windows 上解析行为有版本差异。

### 方案 C：Job Object + WFP callout（不推荐）

Windows Job Object 无原生网络过滤，须 WFP 内核 callout 驱动——体量与维护成本远超收益。

### 方案 D：宿主通道容器化（远期候选）

把 zcode 搬进受控容器（网络限制天然成立）——与 T-Z1 裁定 A（宿主裸跑态，容器内 spawn 不到宿主桌面登录态）冲突，属架构级变更，仅在 A/B 均不可行时重议。

## 4. 推荐与裁决点

- **推荐**：A 为主、B 兜底（A 的 zcode 代理尊重性实测不过时启用 B）。
- **裁决点（蔡工）**：①是否采纳推荐（A→实测→必要时 B）；②白名单初始域集（建议：GLM/MiniMax 模型 API 域 + 供应商遥测必要域，逐域列明后拍板）；③实施排期（独立小轮：实现+白名单配置+审计事件+测试钉+实测留证，预估半天级）。
- **实施验收判据草案**：白名单外域名请求被拒且审计事件落库；白名单内模型调用与 run 全链零回归；`FDE_AGENT_EGRESS_ALLOWLIST` 等配置入 `.env.example` 并登记 README 配置边界表。

## 5. 与 12 条前置的关系

本设计**只消解⑦**；⑧（cancel/进程树回收实测）、⑪（危险操作二次确认以 H1–H13 承载）维持「部分」；①（商用条款书面确认）为外部依赖不受本设计影响。实施后 12 条前置变为 **9 过／2 部分／1 未过（①外部）**——①取得书面确认后 #14 的前置链即清零。
