# SKILL-05 · 移交撤场要点

> 用途：把「人走了」变成「能力留下了」。适用于合同收尾、提前撤场或阶段性退场，目标状态：离场后客户自己转得动、我方不留隐性义务、经验进自己的资产库。

## 适用场景

- 合同约定的服务期临近尾声，进入移交与撤场准备；
- 客户侧已能自主运转，继续驻留的边际价值明显低于成本；
- 双方商定提前收尾，或项目因故中止需要体面退出。

不适用：阶段性请假或临时换人——那是交接（几天的事），不是撤场（把责任整体移出去）。

## 怎么做

### 撤场六件事（顺序即依赖，前一件不闭环不开后一件）

1. **文档成体系**：按「新接手的人第一天要做什么」组织——环境与账号地图；口径文档（验收判据、基线数据、测量方法）；日常操作手册；已知问题与绕行办法。自测法：请一位没参与过项目的人，仅凭文档走完一次典型任务的完整操作——凡是需要打电话问你的位置，就是文档缺口；
2. **能力移交**：客户侧指定接管人，带教到对方能独立完成一次全流程加一次典型故障的首响；带教记录双方签字，不签字不算移交完成；
3. **凭证清退**：我方的临时账号、密钥、令牌、驻场设备逐一撤销并留撤销记录；客户数据的本地副本按约定销毁或移交，双向出清。这一步不干净，前面所有交付在安全与合规上都悬空；
4. **收口确认**：逐项对照验收口径签收；未完成项如实分「已完成／未完成」两栏，写明原因与归属——不把未完成包装成「后续优化」，包装出来的口碑会在续约谈判时连本带利讨回来；
5. **责任窗口**：书面写明离场后我方的响应边界——什么范围的问题、多长的窗口期、通过什么渠道提出；窗口到期日写死。窗口内按约响应，窗口外不默认接单；
6. **经验回流**：复盘归档进自己的资产库——哪类判断被证明有效、哪类坑会重复出现、哪些工件可以复用；经客户允许沉淀的部分转成可复用模板。离场是资产化的起点，不是记忆的终点。

### 可撤场判据（三条全过才提撤场）

1. 客户侧接管人能独立跑通全流程（有带教签字记录为证）；
2. 所有凭证在我方侧零残留（有清退记录为证）；
3. 客户书面确认收口清单（有签字为证）。

三条不过，延长驻留并把缺口列进每周汇报（见 SKILL-04）——撤场时点由证据决定，不由合同日历决定。

### 告别纪律

最后一次汇报按周报三桶结构收口，把「离场后系统自主运转的观察数据」放进第一桶；不留给客户「有事随时找我」式的模糊承诺——要留，就落成明码标价、写死期限的责任窗口。离场后客户自己转不动的系统，说明交付从未完成，只是暂停。

## 人机边界

AI 可以做：起草移交物清单与文档目录骨架；逐项核对文档、签字、清退记录是否齐全；对照验收口径生成收口核对表初稿；把复盘材料整理成资产库条目。

人必须做：撤场时点的拍板；带教完成度的判断；与客户的收口确认和书面签署；凭证清退动作的执行与复核；责任窗口条款的承诺。

红线：AI 不得代签任何确认、不得宣告「移交完成」；撤场判定与对外承诺永远是人。
