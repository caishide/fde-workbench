# SKILL-01 · 售前诊断提问框架

> 用途：把客户嘴里模糊的愿望，问成一句可检验、可定价、可验收的问题陈述。签约定题之前用。

## 适用场景

- 首次接触潜在客户，对方带着「我们想上点 AI」式的开放愿望，但说不清要解决什么、值多少钱；
- 多个干系人对「问题是什么」口径不一，需要在投入方案人力之前统一到一张问题清单上；
- 交付中途发现当初定的问题跑偏，需要重新定题。

不适用：客户已带着明确的、可验收的问题清单来询价——那是方案与报价线（见 SKILL-03）的事，别把来意明确的客户重新拉回闲聊。

## 怎么做

### 四层提问漏斗（从宽到窄，逐层收口）

1. **第一层·现场与注意力**：请对方讲自己的一天——时间主要花在哪几件事上、哪些事反复来打扰。目的：让问题清单从对方的日程里长出来，而不是从你的产品介绍里长出来。
2. **第二层·流程与卡点**：挑一两个高频事项问流转——这件事从发起到办结要经过谁的手、哪一步最常停住、停住之后靠谁去催。目的：把「痛点」钉到流程上的具体位置，钉不住位置的痛点都是传闻。
3. **第三层·损失与基线**：问那一步停住时代价是什么（耗掉的时间、错过的单子、加班的人天），以及现在有没有人在记这个数。没记数的，把「先补一个最小计数」写进建议——没有基线参照，日后一切「变好了」的说法都无从对证。
4. **第四层·边界与门槛**：谁管预算、谁对结果负责（两者常不是同一人）、过去类似尝试怎么收的场、成败由谁按什么标准来判。目的：确认问题背后站着一个能拍板的人，和一把可用的验收尺子。

**收口判据**：你能用对方的措辞，把问题复述成一句可检验的陈述句——谁、在哪一步、付出什么代价、现在的数是多少——并且对方点头认可。复述不出来，说明漏斗没见底，继续问；对方不认可，说明你听偏了，退回上一层。

### 六条资格线（把愿望清单收成切入点候选）

对收集到的问题逐条过，六条全过才算切入点候选，一条不过就挂起并说明缺什么：

1. 当事人具体：能落到有名有姓的岗位，而不是「大家」「相关部门」；
2. 代价可观测：已经有人在记数，或者补一个最小计数就能记；
3. 痕迹在场：相关的数据与流程记录确实存在于对方环境里，且你见过样例；
4. 受益人会配合：改善之后日子立刻好过的那个人，愿意为它出力；
5. 规模够本：值得一次部署的投入，而不是一个脚本能顺手解决的小事；
6. 有人接得住：对方有人愿意认领落地后的日常运营，而不是全指望你。

### 反模式清单（写给自己的坑位记录）

- 拿方案当问题：对方话没说完，你已经掏出产品架构图；
- 问空泛未来式：「您对 AI 有什么期待」——收获一堆客套话；
- 一次抛五个问题：对方只记得住最后一个；
- 用术语压人：对方开始频频点头，眼神已经离场；
- 把汇报会当诊断会：在场的人职级越高，真话越少，去现场找干活的人聊。

### 记录纪律

每次谈话当天落卡，一卡一问题：当事人／流程位置／代价口径／证据现状／下一步动作。隔夜补记等于允许想象参与作证。

## 人机边界

AI 可以做：起草谈话提纲初稿；把会谈纪要整理成问题卡；核对每张卡四层信息是否齐全；按六条资格线机械地筛一遍候选清单并标出存疑项。

人必须做：与客户的一切直接沟通；问题真伪与优先级的判断；是否立项、是否报价的定题拍板；对客户的任何承诺。

红线：AI 产出的诊断结论，未经人逐条复核不得进入任何对客材料；承诺、拍板、收付款永远是人。
