# SKILL-03 · 报价结构与收费口径

> 用途：把一段尚未定价的交付工作，组织成结构完整、边界清楚、可分段收口的报价；并立下给自己用的记账与口径纪律。本文给骨架与自查，不给任何金额——所有数字以双方书面确认的成本核算与客户自身基线为准。

## 适用场景

- 售前定题之后、签约之前，需要出一份报价；
- 交付中途范围要变，需要调整收费口径或补变更单；
- 客户问「能不能按效果付费」，需要一套判断标准而不是拍脑袋。

不适用：纯产品订阅的标价——那是定价策略问题，不是交付报价问题。

## 怎么做

### 报价五段骨架（每段独立可停）

1. **摸底段**：现场调查与问题界定，产出调查报告与问题清单。本段**独立计费、独立收口**——若摸底结论是不适合继续，客户取走报告、结清本段，双方体面收场。把「先卖一次可靠的调查」当独立产品，不把全案风险押在第一段；
2. **定题段**：把选定问题写成双方签字的验收口径——用什么数据、什么方法、达到什么判据算成。本段报价最低但不可省，后面三段的所有边界都由它决定；
3. **实施段**：按口径交付。范围变更一律走变更单，变更单没签字就不动工；
4. **陪跑段**：上线后一段运营支持，按周或按次计，写明响应范围与响应方式；
5. **收尾段**：移交与撤场（见 SKILL-05），写明移交物清单与责任窗口到期日。

### 报价前的自查

- **科目齐不齐**：人力按角色与预估投入分列；差旅与驻场开销单列；工具与算力成本单列（谁的账号、谁付费写清）；风险储备单列——集成障碍点越多、客户数据越乱，这一块越厚。报价前把集成障碍逐项点数（接口、权限、数据搬家、历史欠账），点不清的先写成待确认项，再谈价；
- **口径硬不硬**：报价里不出现效果承诺数字；价值表述一律以客户自身基线为准（例如「改善幅度以验收口径相对贵方现测基线计算」）；市场行情与第三方案例数字不进报价文件；
- **退路明不明**：每段写清「到哪一步、付多少、停了怎么办」——客户看得懂的退路，才是签得下去的报价。

### 四本账分离（记账纪律）

报价本（承诺了多少）、回款本（实际到账多少）、成本本（消耗了多少）、价值本（客户侧可复核的变化有多少）——四本账每周对一次，盯三条差值：承诺与到账的差、到账与消耗的差、消耗与结果的差。任何一条持续拉大都是经营警报。混成一本账的人，会在「有报价」的错觉里以为自己在经营。

### 收费方式选择判据

按结果计费不是信仰，是条件。可考虑按结果计费的**前提**：效果口径能双方书面定义、客户侧基线可测、结果受我方投入的影响足够大、测量过程双方认可。前提缺任何一条，退到里程碑付款——每个付款点对应一段可验收的产出物。折扣与减免永远换条件不白送（减首轮规模、缩陪跑期、换案例授权），无条件降价教会客户下一轮继续压。

## 人机边界

AI 可以做：起草报价文档骨架；按科目清单核对完整性；把历史项目的四本账拉成对比表；检查报价里是否混入效果承诺数字或未溯源数字。

人必须做：定价与折扣的拍板；合同条款谈判与签署；收付款动作；对客户的任何金额与效果承诺。

红线：AI 不得生成「建议报价金额」供直接采纳，金额相关输出仅限按人指定的口径做计算；AI 起草的报价稿必须经人逐条核对并签字后才可发出。
