# SKILL-15 上线陪跑·稳定过渡

上线不是终点，是一段强度递减的护航期：从贴身值守到客户运维独立接得住，中间隔着明确的退出关口。本技能指挥 AI 维护护航期的巡检登记与交棒材料；护航节奏按关口推进，不按固定日历推进。

## 适用场景

- 正式放行后的护航期（从首日起至交棒完成）；
- 客户运维团队需要从「旁观」过渡到「独立处置」时。
不适用：放行判定本身（走上线 go/no-go 决策检查技能）；护航结束后的撤场收口（走移交撤场要点技能）；护航期内发生故障（当场走故障应急响应包）。

## 怎么做

1. 放行当天在项目备忘建护航账：登记放行决定指针、首批范围、客户运维对接人、当前值守安排；护航期所有打扰、变更、演练逐条入账。
2. 关口一「开门」：首批用户首次完成真实业务闭环——判据是业务结果（一笔真实流程跑通），不是系统存活；未达成则每日复盘卡在哪一层，AI 只汇集现象与分诊建议。
3. 关口二「平静」：客户侧高分打扰（影响业务使用的问题）连续清零——「连续多少天」由蔡工按项目定，账里只如实记录每日打扰数，不预设定数；期间 AI 每日起草巡检简报（现象、趋势、建议今日动作）。
4. 关口三「交棒」：客户运维能独立处置常见事件——用一次演练验证：指定一个模拟事件，客户运维走一遍处置，我方只观察不接手；演练通过才启动移交撤场流程。演练不过则登记缺口、约下一次排练，不降标准放行。
5. 全程产出：护航周报草稿（价值呈现按客户周报价值三分法技能口径）；知识转移清单——客户运维需要掌握的处置动作逐条列、配操作指引指针；交棒完成时把遗留观察项逐条移交给撤场流程。

## 人机边界

- 关口放行由蔡工与客户共同拍板；AI 不宣布「已稳定」；
- 打扰分级与响应口径沿用合同承诺或故障应急响应包，不在本技能另立标准；
- 监控与稳定率数字一律取自实测系统面，不编造、不预估；
- 写入与对外逐次确认。
