# SKILL-16 故障应急响应包

故障处置的第一性纪律：先让业务恢复，再找原因；通报先于猜测；全程留痕可复盘。本技能指挥 AI 在故障期间做记录员与分诊参谋——汇集现象、起草通报、维护时间线；处置动作永远由人发起。

## 适用场景

- 交付系统在客户环境发生影响业务使用的故障时；
- 客户报告异常、我方尚未确认影响面时的核实期。
不适用：护航期的例行巡检（走上线陪跑技能，其中发生故障转本技能）；合同承诺条款本身（走 SLA 承诺草案技能）；恢复后的复盘归档（复盘按学习回写技能纪律执行，本技能只产出复盘输入包）。

## 怎么做

1. 定急迫度两问（不设固定分级表）：①业务还在转吗——停摆、降速、正常三态；②有没有绕行办法——能绕、不能绕。两问答案组合决定通报对象与投入力度；具体时限以合同承诺为准，合同未约定时当场口头约定并记入时间线。
2. 两线并行纪律（人各其职）：恢复线由处置人负责——优先让客户先用起来，降级、回滚、旁路三途按现场条件选，AI 可列各途前置条件但不代选；查因线由另一人负责——同步取证（现象截图、日志指针、变更记录）。两线互不阻塞；人手不足时恢复线绝对优先。
3. 通报三句话纪律（逐次更新，报文式而非表格）：第一句现状（什么现象、影响谁）；第二句正在做什么与下次通报的具体时刻；第三句需要客户做什么（如有）。AI 起草每次通报草稿，蔡工审定后发出；通报只陈述已证实现象，未经证实的猜测不进通报。
4. 时间线逐条登记（AI 实时维护，进项目备忘；每条＝时刻、动作、发起人、结果）；恢复确认后补一条「客户确认恢复」。
5. 复盘输入包：恢复确认后的次日（时限按项目定，AI 只提醒不强制）汇集——时间线全量、根因结论占位（由人填写）、影响面估计、防复发候选动作；随后按学习回写技能的三路回写纪律归档（技术事实进技术备忘、取舍进决议、跨项目规律进通用学习）。

## 人机边界

- 处置动作（回滚、降级、改配置）永远由人发起并执行，AI 不碰生产环境；
- 通报对外逐次经蔡工审定；猜测与未证实归因不进对外通报；
- 时间线只记事实与指针；涉客户资料按脱敏纪律处理；
- 根因结论由人定，AI 只提供候选解释并标注证据强弱。
