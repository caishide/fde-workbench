# SKILL-13 SLA 承诺草案

SLA 是写进合同或服务说明的可测承诺：承诺什么、怎么量、量不到怎么办。本技能指挥 AI 起草承诺草案，每条都带测量口径与责任归属；无来源数字不落正文。

## 适用场景

- 合同或服务说明需要写服务承诺条款时；
- 客户问「出了问题你们多久响应」，需要书面口径时；
- 复核既有承诺（我方到底接不接得住）时。
不适用：报价与收费结构（走报价结构技能——那份管怎么收钱，本篇管承诺什么）；运维排班本身。

## 怎么做

1. 用项目查询工具汇集：客户业务关键时段、既有沟通中的期望表述、我方值守与升级资源现状、系统监测能力面。缺实测数据的能力项一律标「待实测」，不凭印象填数。
2. 把承诺落到客户可感知的结果上再翻译成指标：先写客户语言（如「核心查询在工作时段可正常使用」），再配测量口径——在哪里测（监测点）、多长窗口算一次、分母是什么（排除维护窗口、客户侧网络、第三方故障等）、窗口内允许的未达标余量及耗尽后的动作。
3. 每条承诺自检四问，任一答不出即降级为待澄清：测得到吗（有监测点与口径）／谁来负责（有责任角色）／做不到怎么办（补救与补偿口径占位）／依赖方故障算谁的（第三方与维护期已排除或已说明）。
4. 配套事件机制草案：事件怎么分急缓（分级口径交给故障应急响应包技能，不在此另建一表）、各档通知对象与通知顺序、升级到谁。承诺数字只能来自三处——我方实测记录、既有合同先例、客户明示要求；三处都没有就标待澄清上浮。
5. 产出草案文档（状态三值：可执行／有阻塞／待复核），蔡工逐条确认后归档。评审核对：每条承诺有测量与责任人、维护与依赖故障的排除项写清、全文无凭印象的数字。

## 人机边界

- 无来源数字不入正文（与产品数字溯源纪律同尺）；估断必须标注；
- 承诺即法律责任，最终条款由蔡工与法务拍板，AI 只起草；
- 承诺不超出我方可测可配的资源：无夜间值守就不得写全天候人工响应；
- 写入与对外逐次确认。
