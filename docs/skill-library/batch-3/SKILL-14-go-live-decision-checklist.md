# SKILL-14 上线 go/no-go 决策检查

试点转正式上线前的最后一道人判闸：证据齐不齐、例外批没批、谁说了「放行」。本技能指挥 AI 汇集证据、起草决策材料、主持过会流程。清单本体的唯一权威是产品门禁面——本技能不复述清单内容，只管把这次会开成可复验的决定。

## 适用场景

- 试点即将进入客户真实业务流的放行决策前；
- 大版本更新或大范围配置变更需要一次正式 go/no-go 时。
不适用：日常小版本的内部发布（走既有研发发布面）；门禁清单本身的增删（产品门禁面的权威，本技能零改动）。

## 怎么做

1. 用项目查询工具汇集放行证据：发布物与版本定格、评测与验收报告、身份与权限配置核查记录、容量与监测告警就绪记录、备份与回滚演练记录；每样登记指针与指纹，不搬运原件。
2. 起草决策材料（文档生成，标「草稿·待过会」）：逐项「检查项—证据指针—责任人—状态」，状态只认三种——证据可复验通过、有已批例外、缺失；缺失项直接挂「不通过候选」，不得空勾。业务侧与运维侧的验收分开登记、各设签字位，互不代替。
3. 例外纪律：任何「先上线再补」的例外必须带三样——例外内容、失效期限、责任人；无期限无责任人的例外视为未决，材料里标红。
4. 会前三问过一遍：回滚可行吗（回滚依赖不可逆数据变更时，必须补上备份恢复与向前修复两案才可过会）；no-go 条件写了吗（先立「什么情况必须停」，会中才不会被现场气氛推着走）；灰度范围定了吗（首批放给谁、多大范围、观察什么信号）。
5. 会中产出决定记录：go、no-go、有条件 go 三值之一，逐项证据指针随决定归档（走既有门禁证据口径：指针＋指纹，原件留工作目录）；决定与例外经蔡工签认后写入项目备忘。放行后转「上线陪跑·稳定过渡」技能护航。

## 人机边界

- 决定由人做：AI 汇集证据、起草材料、复述决定，不代投 go/no-go；
- 缺失关键证据不得勾选通过；例外无期限无责任人不得入材料；
- 证据只存指针与指纹，原件永不入库（门禁证据红线同尺）；
- 写入逐次确认。
