# SKILL-11 干系人决策地图

把客户组织里「谁关切什么、谁拍板什么、卡住时找谁」画成一张可复验的地图，供立项、范围争议与跨部门移交时使用。本技能指挥 AI 从真实批复痕迹反推决策链，产出草稿地图。

## 适用场景

- 立项后需要摸清客户侧决策链时；
- 范围、验收、付款出现争议，需要找对签字人时；
- 跨部门移交或关键人可能变动时。
不适用：平台内部的权限与可见性配置（那是产品权限模型的领域，本技能零接触）；只想泛泛了解组织架构而无具体交付任务时。

## 怎么做

1. 用项目查询工具汇集既有材料：合同签署记录、往来沟通里的批复线索、纪要中的表态记录。从一项真实发生过的审批事项反查实际批准人与实际否决点——口头头衔不算数，批复痕迹算数。
2. 逐人登记四个观察面（都从批复与提问记录归纳）：其关切什么；其职责范围内的事项变化对其工作意味着什么；其对哪些事项有否决或拖延能力；可观察的阻力行为——只记行为与职责，不推断性格与动机。
3. 为范围、验收、数据、运维四个域各标注唯一拍板人；发现两人共签或「都说了算」，视为未决项列出，不默认处理。
4. 为每个域草拟升级路径：卡住时下一站找谁、多久没有回音即升级；用一次假想冲突（如「验收标准双方理解不一致」）演练该路径，走不通的环节改立待澄清。
5. 产出草稿地图（状态三值：可执行／有阻塞／待复核），每条登记信息来源与待确认项；关键证据（数据授权人、预算拍板人）缺失时不猜测，输出 blocked 并给最小补证动作。蔡工确认后写入项目备忘。

## 人机边界

- 只汇集公开与授权材料中的批复痕迹；阻力只以职责与可观察行为描述，不做性格推断；
- 地图是草稿与建议；谁拍板由客户组织事实决定，AI 不指派；
- 数据所有者未确认时，不得默认业务对接人有权授权数据；
- 写入逐次确认；地图不进对外材料，除非蔡工审定。
