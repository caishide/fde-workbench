# SKILL-06 · 客户上下文简报（会话开场装载）

## 适用场景

- 每次围绕某个项目的会话开工第一步：只要要谈某个项目、而本会话还没有装载过它的背景，先跑本技能，再谈别的。
- 典型时机：隔了几天回到某个项目、接手他人交接的项目、执行任何交付动作之前、蔡工说「看看某项目现在什么情况」。
- 定位是开场件不是收尾件：装载完成后，复盘类技能按其触发点另行调用；跨项目的全景盘点归「跨项目紧急度排序」管，不在本技能内。

## 怎么做

1. **装载**：用项目查询类工具读取当前项目的授权材料——项目基本信息、近期备忘、事件记录、产物指针；只在授权与可见范围内读取，范围外的材料当作不存在，也不向蔡工提及范围外有什么。
2. **出简报**：把读到的东西汇总成开场简报，五块固定——
   - 项目现状：三至五条，取自基本信息与最近的决定；
   - 未决问题：按优先级排列，逐条带出处（哪份材料、哪天留下）；
   - 当前阻塞：高优先在前，无则明说「无活动阻塞」；
   - 漂移：对比最近一次记录时间与当前内容，概括「自上次记录以来变了什么」；首次装载的项目明说「首次装载，无漂移可比」，并顺势引导补齐基本盘（客户背景、技术栈、干系人、时间线四样）；
   - 建议的第一个动作：一句话，指向最高优先级的阻塞或未决，说清为什么先动它。
3. **问增量**：问一句「有什么要更新的吗」。把回答按内容分流归档：人员与干系人变动→组织类备忘；新系统、接口、环境、数据格式→技术类备忘；新日期与节点→时间线；新阻塞→阻塞项；新未知→待澄清；已敲定的事→决议记录。一条回答看着能进两处时，先问再写，不猜。
4. **确认后落笔**：写入前先把「准备写什么、写到哪」列给蔡工过目，确认后才执行备忘写入；被拒绝就不写，并如实提示下次漂移提示可能把这几天的变化合并显示。每条更新注明当日日期。
5. **无增量就收**：没有要更新的，明说「上下文已是最新」，简报照常交付，不硬凑更新。

## 人机边界

- AI 只做汇集、分流与起草；任何写入动作逐次经蔡工确认，不批量自动落笔。
- 事实层原话不改写：纪要与客户原话是引用面，简报里的转述要标明是转述。
- 只装当前项目的料；跨项目规律一律不走本技能（归「POC 收尾复盘·学习回写」的学习通道管）。
- 漂移只做提示，不做推断：读不出来的变化如实说读不出来，不脑补中间发生了什么。
