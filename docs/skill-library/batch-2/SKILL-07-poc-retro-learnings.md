# SKILL-07 · POC 收尾复盘·学习回写

## 适用场景

- 一次 POC／验证性工作收尾时必跑：POC 结束而没有任何回写，等于这次验证的学费白交。
- 也用于按周对单个项目做阶段复盘（「这周都干了啥、什么卡住了」）。
- 触发语：POC 跑完收尾、阶段收尾、周五回看、蔡工问「这周交付了什么」。

## 怎么做

1. **汇集活动**：读取窗口内（默认最近一周，可指定起日）的事件、备忘变更、产物指针，整理成活动清单——发生过什么、动过哪些记录、产出了什么。
2. **四问复盘**，逐问过、逐问等蔡工补充：
   - **交付了什么**：活动清单打底，蔡工补充场外完成的事项（口头拍板、场外评审这类不落记录的也算）；
   - **什么卡住了**：列高优先阻塞与高优先未决，每条标注「本周新出现／上周延续／更早——须升旗」；同一条卡点连续两轮复现的，单独列「升级提示」——重复出现说明当前解法不对，要换打法不是再等一周；
   - **学到了什么**：本窗口新做的决定逐条过一遍；再问一句「有没有适用于其他项目的规律」；
   - **下一步**：未来两周的节点逐条列，追问「下个节点要成立，得先满足什么」——答案里常藏着新未决项。
3. **POC 收尾时强制三路回写**（本技能的核心步，跳过即视为未完成）：
   - 关于客户环境的新技术事实（接口行为与文档不符、环境限制、数据的真实形状）→ 技术类备忘；
   - 做过的取舍及理由（选了什么、放弃了什么、受哪个约束驱动、对后续生产化的含义是什么）→ 决议记录；
   - 可能适用于其他项目的规律（某类系统的通病、某类做法特别有效、某处文档误导）→ 通用学习备忘（跨项目通道）。
4. **零收获追问一次**：三问全答「没有」时，追问一次——要么这验证本就不用做，要么没留意；追问之后尊重蔡工的结论，不纠缠。
5. **新未决回灌**：复盘里冒出来的新未知，写回待澄清备忘并注明出处（哪天的复盘提出），让它在下次开场简报里继续可见。
6. **收尾**：回写内容经蔡工确认后落笔；POC 代码与临时产物不入库，只登记指针与 sha256 指纹；复盘正文按「交付了什么／卡住了／学到了／下一步」四节成稿。

## 人机边界

- 结论、取舍、升级判断由人拍板；AI 只汇集、提问、起草。
- 三路回写各走各的通道，不混写；跨项目规律里不得出现任何客户真实资料，只写规律本身。
- 复盘不改写历史记录，只追加新记录；发现记录与事实矛盾时如实摆出矛盾，不擅自修正。
