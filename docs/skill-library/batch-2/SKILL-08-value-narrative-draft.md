# SKILL-08 · 价值论证段起草

## 适用场景

- 需要向客户决策层讲清「这件事值得做」时：立项沟通前的价值梳理、汇报材料里的价值段、续约前的价值盘点。
- 与《报价结构与收费口径》（SKILL-03）分工明确：那份管「我方如何计费」，本篇管「客户能得到什么」——一起用，互不替代，数字互不混用。

## 怎么做

1. **定主杠杆**：从项目材料确认这笔价值主要落在哪个杠杆上，五选一——时间（省下的工时、缩短的周期）、差错（减少的返工与升级）、资金（释放的占用）、增量（新增的产出或收入）、风险（避免的损失）。次要杠杆只进附注，绝不并入主数。
2. **写显式取值式**：把「价值怎么算出来」写成清楚的变量式；变量超过四项说明想一口吃太多，拆成主论证加附注。
3. **假设标三态**：取值式里每个变量标明来源三态之一——**实测**（来自客户自己的数据）、**引证**（公开出处，注明出处名）、**估断**（经验判断，必须带「估断」标记）。估断占比过半时明说「本论证以估断为主，说服力有限」。
4. **算三个口径**：保守／基准／进取各算一遍，偏离幅度由本次使用者自定并在文中写明。三口径过近说明不确定性被藏起来了，追问「真正的不确定在哪」，答不出来就把这一条挂进待澄清。
5. **防御预演**：问一句「对方的决策者最先会质疑哪里」——质疑算式（口径怎么来的）→ 补出处；质疑数字（量偏大）→ 回到数据出处；质疑方向（我们已经在做）→ 这不是价值问题，退回需求澄清。
6. **含糊项上浮**：所有答不严实的点单独列「待澄清」，在解决之前不进正文结论，只进附注；产出为论证段草稿，交蔡工审改后才能对外使用。

## 人机边界

- **无来源数字不入正文**：正文里出现的每个量值都必须能在客户数据、已注明出处、或带「估断」标记三者中对上号；对不上的写「待澄清」，不编数——与产品的数字溯源纪律同尺。
- AI 只起草；对外口径、幅度、取舍由蔡工拍板。
- 不替客户承诺收益：草稿里的价值是「论证」不是「保证」，措辞上保持可辩护的保守。
