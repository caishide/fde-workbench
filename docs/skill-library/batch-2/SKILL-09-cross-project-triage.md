# SKILL-09 · 跨项目紧急度排序（只读）

## 适用场景

- 没有指定项目、想知道「今天先看哪个」时：一天开局、周初盘点、多项目并行时的取舍时刻。
- 它是跨项目的只读视角；进入单个项目之后，改用「客户上下文简报」装载该项目的完整背景。

## 怎么做

1. **可见性是硬边界**：只在当前操作者可见范围内的项目里取数——平台的项目可见性过滤是本技能的世界边界，过滤之外的项目不存在、不提及、不计数。
2. **先定范围**：默认看近期活跃的项目；可以收窄到「有高优阻塞的」，也可以铺开看全部。项目数量多时先问蔡工要不要收窄，避免把上下文摊薄到每家都看不细。
3. **逐项目提取**：每家取五样——所处阶段、高优阻塞、高优未决、两周内的节点、最近一次动静的时间。
4. **排序原则**（原则排序，不硬编码权重，蔡工可调）：
   - 七日内要到的节点压倒一切：一个临期节点重于一批悬而未决的问题；
   - 其后是有高优阻塞的项目；
   - 再次是高优未决多的项目；
   - **未决计数设上限**：未决越积越多更像疏于照看，而非更紧迫——设上限防止调研期项目（天然未决多）压住交付期项目（有真节点）。
5. **出简报**：按紧急度从高到低逐家列：项目名、一句话现状、阶段、高优阻塞、高优未决、两周内节点、最近动静；末尾给一句「建议的第一个动作」，指向榜首项目最急的那条。
6. **全程只读**：不改任何记录、不写备忘、不留任何标记；蔡工看完自定先后，然后按项目进「客户上下文简报」。

## 人机边界

- 可见性过滤器之外零泄露：排序简报里连「还有若干项目不可见」这类元信息也不出现。
- 只读零写入是本技能的身份；任何写动作都说明走错了技能。
- 排序是建议不是指令；权重的可调不等于权限的可调——越权动作照旧走平台权限，不因「紧急」放行。
