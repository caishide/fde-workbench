# SKILL-04 · 客户周报价值三分法（v2）

> 用途：把每周的客户汇报，从流水账改造成一个让管理层三分钟读完的信息工件——价值可对证、风险不藏掖、决策有出口。常态运营期每周用，试点期同步发起人也可用。
> v2（2026-11-12）：在 v1 三桶＋五块骨架之上，并入「决策导向三件」补强——拍板事项三要素自查、读者分型详略、追问预判备询（补强素材来源见文末对照表 v2 行，均为严档仅思想）。

## 适用场景

- 交付进入常态运营后，每周向客户（尤其客户管理层）例行汇报；
- 试点期向发起人定期同步，需要对方持续给资源与耐心；
- 阶段性汇报（月报、结项报告）的正文骨架。

不适用：事故通报（要走专门的告警通道，不等周报）。

## 怎么做

### 核心纪律：先定证据状态，再写内容

每一条进展，先问自己「这话有什么证据」，按答案分进三桶，桶与桶不许混——

- **第一桶·已坐实**：客户侧可复核的变化，且以客户自己动作之前测得的基线为参照。写法固定：一句价值陈述＋基线值＋现值＋数据出处。没有基线参照的变化，不许进这一桶——无论它看起来多漂亮；
- **第二桶·在做**：有明确动作、尚无结论的事。写法：动作＋当前所在步骤＋预计何时能拿到可判读的结果。不写预期收益数字——没发生的事没有数字；
- **第三桶·存疑**：听着不错但证据不足的变化（只有个别用户叫好、口径不清、样本可疑）。写法：现象＋缺什么证据＋补证计划。这一桶是周报的诚实担当——它防止第二桶的东西被提前当成成绩汇报出去。

对照意识（v2 补强）：能安排对照或分批放开的场景，第一桶的价值表述带对照口径（同一时段未改造的部分作参照），比只做前后测更有说服力；做不了对照的，明说「前后测口径」。

### 周报五块骨架（自上而下）

1. **头条一句**：本周最值得客户记住的一件事，从第一桶里挑；第一桶空着就写「本周无可坐实变化」——空也是信息，硬凑才是伤害；
2. **三桶明细**：每桶最多三五条，超了说明该拆专题另报；
3. **需要客户拍板的事项**：每条写明到期未决时的默认处理方式——把不决策的代价显式化，催生决策而不是积压决策；
4. **风险与求助**：只写影响验收口径或客户利益的风险，并写清需要对方给什么配合；
5. **下期观察点**：下周将产生可判读结果的一两件事，给读者一个下周还打开的理由。

### 拍板事项三要素（v2 补强）

第 3 块的每条拍板事项，发出前过三要素自查，缺一不齐：**结论**（要对方定什么，一句话）、**证据**（支撑这个决定的最小事实集，指向第 1／2 桶条目）、**请求**（请对方在什么时候、以什么形式给答复）。向管理层汇报的本质是索取决策，不是通报进展——三要素缺任何一件，读者只能「收到」，不能「拍板」。

### 读者分型与追问预判（v2 补强）

- **读者分型**：同一份周报按读者角色调详略与头条——管钱的人先看成本口径与投入产出、管业务的人先看流程与交付变化、发起人先看趋势与风险；一份周报多类读者时，头条照顾发起人，明细分节照顾其余；
- **追问预判**：发出前预判管理层最可能追问的三件事（通常是：数怎么来的、为什么慢了、还要多少钱），正文写不清的就补一页备询附在文末——被追问时翻得出，比临场解释可信。

### 写法纪律

- 全文用客户的业务语言，不出现我方内部工具名、模型名与代码名词；
- 每条带证据指针——哪张报表、哪个系统、哪次测量，让人能顺着查；
- 坏消息放固定位置不挪窝：客户对「永远的好消息」的信任衰减，快于对坏消息本身的反感；
- 全文不出现无法溯源的百分比；所有幅度表述以客户自身基线为准；
- 篇幅服从三分钟读完的约束——写不完是拆分信号，不是压缩信号。

## 人机边界

AI 可以做：从交付记录与系统数据汇总三桶候选条目；逐条核对证据指针是否真实在场；检查是否混入未溯源数字与内部名词；起草周报初稿；核对拍板事项三要素是否齐全；按读者分型起草不同详略的变体；起草备询页初稿。

人必须做：三桶归属的最终判定；价值陈述的措辞定稿；发送动作；对客户的口头补充与承诺。

红线：AI 不得替周报报喜不报忧、不得弱化或删除第三桶条目；对外价值判断与承诺由人签字负责。
