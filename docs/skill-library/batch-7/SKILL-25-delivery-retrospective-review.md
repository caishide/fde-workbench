# SKILL-25 交付复盘

项目或一个交付阶段做完，要回答的不是「谁没做好」，而是「哪些经验下次还用得上、哪些只是这次的补丁、下次具体改哪一处」。本技能指挥 AI 把事实摊平、把归因落到可改的地方、把改进项写成有人有验收物的条目，并把可复用的那部分回灌到既有面。

## 适用场景

- 一个项目或阶段收尾，需要一次能落成改进项的复盘；
- 同样的问题在第二个项目又出现一次，要判断它是不是流程里缺了一环；
- 交付过程中改过方向、砍过范围、换过做法，想把当时的判断依据留下。
不适用：事故发生时的应急处置（走故障应急响应包）；POC 结束时的收尾回写（走 POC 收尾复盘技能）；把案例沉淀成可训练素材（案例语料走训练场的案例导入通道，不在本技能做）。

## 怎么做

1. 先定这次复盘要回答的一个问题：一次只问一个（例如「为什么工期比预计长」「为什么同类问题反复出现」），把问题写在材料抬头，避免复盘变成流水账。
2. 铺事实只用手上有的：时间线、当时的决策记录、交付与验收记录、指标、客户反馈逐项摊开；找不到原始记录的地方标成回忆，并把回忆与记录分开写，不拿回忆当记录用。
3. 归因分三类落位：判断当时就错了、执行时偏离了、外部条件变了；每条归因都要指到具体一处可改的地方（一次决定、一个动作、一个交付物、一个接口），指不到具体位置的归因只是感想，不写进结论。
4. 分流三类产出：可复用规则（换个项目仍然成立，且写清适用边界与不适用边界）、只此一次的补丁（写清为什么这次能凑合、下次不能照搬）、原因仍未定（写清缺什么证据才能定，不硬给结论）。
5. 改进项写成有主、有验收物、有复查时点的条目：谁去改、改成什么样算完成、什么时候复查；没有负责人的改进项不算改进项，先进待认领清单。
6. 回灌只走既有通道：可复用规则写进跨项目通用的学习备忘，指向已入库的相关技能或既有台账条目，不另立一份平行文档；项目内的过程事实留在项目工作目录，仓库侧只留指针＋指纹。

## 人机边界

- AI 做：整理事实时间线、分类归因、分流三类产出、把改进项写成条目、起草回灌文稿；
- 人做：定复盘要回答的问题、确认归因站不站得住、认定改进项的负责人与验收物、拍板哪些结论对外说；AI 不代替人下「谁的责任」的结论，不替人承诺整改期限；
- 归因纪律：不写「谁没做好」，写「哪一处判断或动作可以换」；未定的成因如实记未定；
- 红线：客户真实资料只留工作目录，本仓与交付面只存指针＋指纹；
- 写入逐次确认。
