# SKILL-26 POC 转生产

验证做完、指标也过了，接下来是把东西搬进真实业务环境并让人真的用起来。本技能指挥 AI 把 POC 与生产的差异摆成清单、逐项过「不能直接搬过去的东西」、定分批放开的进入与退出条件、把值守与交接落到具体人；转段结论由人拍板。

## 适用场景

- 客户要结束验证期，把试点成果搬进正式环境真实跑起来；
- POC 指标达标，但生产环境与验证环境差别明显，需要先补齐才能放量；
- 已经放出去一小批，要定下一批放给谁、什么条件才放、以及出事退回去。
不适用：验证开始前的环境与验证口径准备（走 POC 环境与验证速查）；部署形态怎么选（走部署形态速查）；上线之后的护航与稳定过渡（走上线陪跑技能）；上线放行决策本身（走上线 go/no-go 决策检查）。

## 怎么做

1. 先确认转段的前提成立：验证结论是可复验的（同样的口径再跑一遍仍然成立）、验收标准客户已经认过、没验证过的假设单独列出来；前提不成立就不进转段，先把结论收窄或补测。
2. 把 POC 与生产的差异摆成清单，至少覆盖这几类：流量形态与并发压力、数据规模与敏感度、身份与权限体系、可用性与备份恢复、可观测与告警、对外集成与依赖方；每类写「生产要什么／现在有什么／差在哪／谁来补／补完怎么验」，没有负责人与验收物的差距不进清单。
3. 逐项过「不能直接搬」的东西：验证期用的临时凭据、临时账号、临时数据、放宽过的审批与配额，一律按生产口径重来——凭据走正式签发，数据按生产分类与脱敏要求处理，例外要单独走例外流程而不是顺手带过去。
4. 分批放开，每批自己写三样：进入条件（这一批放开之前必须已经就绪的项，逐条可查）、观察面（谁在看、看哪几个信号、看多久）、退出条件（出现什么就退回上一批或停掉，退回去怎么做）。第一批从影响面最小的一批开始。
5. 值守与交接落到人：业务侧的采纳负责人与技术侧的值守负责人各写清楚谁、值守看什么、交接给谁；转段期间业务与技术两侧的采纳与稳定情况要分别取证，一边通过不代表另一边通过。
6. 转段完成的判定与例外：隔离与恢复能力没验证过的，不许宣布转段完成，只能保持验证态；宣布完成前把差距清单逐条销账，未销的写成遗留项交给人决定。

## 人机边界

- AI 做：整理差异清单、起草分批放开的进入与退出条件、起草值守与交接清单、汇总销账进度；
- 人做：确认转段前提、判断哪些差距能带过去、拍板放批与退批、决定转段完成与例外、承接业务采纳确认；AI 不代客户确认采纳，不代拍放量节奏；
- 红线：验证期产生的临时凭据与临时数据不进生产，凭据走正式签发；客户真实资料只留工作目录，本仓与交付面只存指针＋指纹；
- 写入逐次确认。
