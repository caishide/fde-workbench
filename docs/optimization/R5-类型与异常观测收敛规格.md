# R5：类型与异常观测收敛规格（最小面）

更新：2026-11-23。范围只做一项类型基线收缩和一项既有 503 防御路径的可观测性补强；不改 API 契约、错误码、状态码、迁移、路由和桌面。

## 1. 问题

- `projects/gantt.py` 有 3 处集合缺显式注解，mypy 基线长期吸收：`active_dates`、`dependency_ids`、`incomplete_ids`。
- `projects/service.py::create_project` 的 catch-all 把非预期异常转成 503 `project_creation_failed` 时保留 `from None`，间歇性 CI 失败时缺少异常分类线索（2026-11-22 QR004/QR018 同族实录）。

## 2. 实施面

1. `projects/gantt.py` 增加精确集合注解；运行时排序、序列化和返回结构零变化。
2. `projects/service.py::create_project` 使用应用日志记录固定事件名 `project_creation_failed` 和异常类名。保留 `from None` 与原有 code/message/status。
3. 新增服务层异常路径钉：在排程依赖处注入带合成 SQL 和绑定参数的 `StatementError`。断言固定 503 响应、日志事件及异常类名，并验证日志无异常对象、SQL 或参数。
4. `server/mypy-baseline.txt` 只用 `scripts/check-python-types.py --update` 收缩；禁止放宽判据、skip 或删除既有测试。

## 3. 基线与验收

- 改前实测：`scripts/check-python-types.py` 输出 `baseline 277 occurrences / 102 distinct, current 277`；gantt 相关 3 处均为 `var-annotated`。
- 改后要求：基线收缩到 `274 occurrences`，`current 274`，无新增错误；检查输出不得出现 “3 resolved” 的可收缩提示。
- 目标测试红→绿：新增隐私回归测试应检出缺少分类事件和完整异常日志两类回归。
- 回归：gantt 与项目创建相关目标切片通过；提交钩子全套通过；PR/push 两组四项 CI 通过。
- 文档同步：PROGRESS 记录 R5 交付与实测数字；CHANGELOG 记录行为外的可观测性、类型与基线变化。

## 4. 边界与回退

- 不尝试一次清空 277 条存量 mypy 基线；不重构 projects/service.py，不触发热点行数预算的方向性增长。
- 日志字段限固定事件名与异常类名。异常正文、堆栈、SQL、绑定参数及请求数据均排除在日志之外。QR004/QR018 间歇失败的根因待下次取证。
- 回退方式：还原 `gantt.py`、`service.py`、新测试、mypy 基线和本规格；无数据库、部署或数据迁移副作用。
