# R4 容量基线与离线汇总规格

## 交付范围

R4a 提供标准库 CLI `python scripts/metrics/capacity_rollup.py <trace.json>`、合成测试及既有 metrics CI 覆盖。写入范围为 CLI、`tests/metrics/test_capacity_rollup.py`、本规格、`PROGRESS.md`、`BLOCKED.md` 和 `CHANGELOG.md`。回退可撤回此轮提交，工具只读输入文件并写标准输出。

R4b 在获准的隔离栈逐档采集并建立基线。R4c 按实测热点实施变更，以同档负载复测。报表聚合是待测候选，先记录时间、内存及分母，再决定是否改动。

## 采集口径

每份文件对应同一场次、同一负载档位。每条记录对应一项合成任务，从最初操作到截止点，包含任务内的重试及其终态。采集端按任务归并，每项任务只交一条记录。源时钟由采集端统一对齐，所有区间使用同一个场次起点的整数毫秒偏移。

| `chain` | 用户链 |
|---|---|
| `open_project` | 登录并打开可见项目 |
| `save_research_plan` | 保存调研或方案 |
| `background_generation` | 后台生成提交至终态 |
| `evidence_approval` | 证据提交及由授权角色审批 |

| 区间字段 | 起止锚点 |
|---|---|
| `request` | 客户端发起请求至收到响应、超时或失败，每次请求单记 |
| `queue` | 本次作业开始可供领取至实际领取，延期生效前的时间另记在场次记录 |
| `execution` | worker 领取至本次执行完成、失败或取消确认 |
| `human_wait` | 确认已可进行人工处理至人工提交处理结果 |

`BackgroundJob.available_at` 表示可运行时间，租约表示当前持有状态。精准拆分需要采集端留存领取和结算边界。仅有轮询或更新时间时，相关字段填 `null`。一类区间内若只测到部分重试或请求，该类整体填 `null`。阶段未进入时填 `[]`，例如提交失败而未进入待审。阶段已进入但截至场次截止尚未结束时填 `null`，例如作业可领但尚未领取、执行尚未结束或已待审但尚未审批。在场次记录标识截止点。v1 场次在单项任务内串行发请求，并发以任务为单位。

## 输入和输出

根对象仅含 `schema_version: 1` 和 `samples` 数组。每条样本仅含 `chain`、`outcome` 与上述四个区间字段。`outcome` 取 `succeeded`、`recovered`（失败后恢复并达成）、`failed`（终态失败）、`incomplete`（截止时尚无终态）。每个区间字段取 `null`（缺测）、`[]`（本任务未经过该阶段）或按时间排序的 `[start_ms, end_ms]` 列表。端点范围为 `0` 到 `2^53-1`，可相接，可等长。相同阶段的区间不得重叠或倒序。不同阶段允许重叠，例如首个请求尚未返回时作业已被领取。各阶段耗时分别统计，四段之和没有端到端历时语义。

```json
{"schema_version":1,"samples":[{"chain":"background_generation","outcome":"recovered","request":[[0,12]],"queue":[[8,15],[40,52]],"execution":[[15,30],[52,80]],"human_wait":[]}]}
```

每条用户链固定出现在结果中，输出样本数、各终态计数、四阶段的 `measured`、`missing`、`not_applicable` 计数及 `p50_ms`、`p95_ms`、`max_ms`。分位数按最近秩（排序后取 `ceil(p*n)` 位）计算，输入值为一项任务在该阶段的累计耗时，所有结果的已测样本进入分布。空分布分位数和最大值为 `null`。示例任务的请求、排队、执行分别为 12、19、43 ms，人工等待计入 `not_applicable`。

采集端将不超过 4 MiB 的 UTF-8 JSON 保存为本地普通文件，在隔离环境中调用 CLI。CLI 拒绝显式 UNC 路径和非普通文件。部署责任人通过环境隔离约束出站，输入路径须位于本地存储。参数错误也返回固定错误码。重复键、未知字段、未知枚举、布尔端点、负值、间隔反转和重叠均 exit 2。错误为 JSON，含固定 `error`，适用时含固定 `field` 与从零起算的样本 `index`。输出只使用固定字段、枚举及汇总值。

## 红队检查与验收

| 承重假设 | 最便宜的证伪测试 | 停止或改线条件 |
|---|---|---|
| 生命周期事件可还原队列与执行 | 人工标注一条带两次尝试且请求与排队重叠的合成轨迹，核算三段 | 领取锚点缺失时登记缺测，停用该段实测对比 |
| 分布真实反映失败和截尾 | 混入失败、恢复、截止未完成及零耗时样本，核计数和分位数 | 失败被丢弃、缺测被补零或四段相加均不通过 |
| 可安全在隔离栈逐档加压 | 开跑前复核环境身份及合成数据、外连约束、资源上限和停止条件 | 任一条件无法取证时只做离线验证 |

R4a 验收使用合成输入，含真实 CLI 正反例及固定错误回执。R4b 待部署责任人确认独立 API、worker、数据库、Redis 和文件目录，可复位的合成数据，后台生成测试替身，参与角色、资源上限及停机阈值。逐档记录提交 SHA、场景种子、并发、时限、完成/失败/恢复、CPU、内存、队列积压和每段样本量。场次有丢样或无法核实源时钟时须补测。R4c 固定场次参数复验，并核对角色隔离、任务成功语义及统计分母。任何容量结论须引用 R4b/R4c 场次证据。
