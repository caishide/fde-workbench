# Ecosystem OS M3 人工首片试点走查手册（备件 v1）

**性质**：**只备件，不代办**（M2 批次三 D 节纪律沿袭）——本手册是人工首片试点走查的操作底稿；**场次、三方人选、时间由蔡工亲自定**，AI 不代发起、不代选人、不代走查、不代结论。
**依据**：D-6 拍板（维持人工待办：真实试点场次与三方人选、换人复跑——修订七第 5 条）＋「按建议实施」授权（2026-11-24 交互式：本手册＝建议的备件加强件）。
**上游**：`docs/ecosystem-v1/m2/PROGRESS.md` 批次三任务 D 节（薄切片招募观察表字段／DIFF-09 样单六要点）；本手册把「走查」面从字段级扩成可执行的分步脚本。

---

## §1 走查目标与判停线

| 项 | 口径 |
|---|---|
| 目标 | 一个真实试点场次在**活体系统**上走通「伙伴申请 → 区域线索认领 → 派单收件箱三态分流 → 接单 → 结算可见」全链，验证 M3 候选 1＋2 的界面在真实人手上可用 |
| 判停线（任一命中即停） | ①任何步骤需要**真实客户资料**进入系统 ⇒ 停（红线：代号化后才可录入）；②售卖闸任一条件缺件 ⇒ 闸相关步骤只走查看面，不触发写面；③发信/扣费/签约任一真实动作被触发 ⇒ 立即停并回报 |

## §2 三方人选（蔡工亲自定，AI 不代选）

| 席位 | 建议来源（仅供定人参考，非人选） | 走查中做什么 |
|---|---|---|
| 区域伙伴（R4 视角） | 待蔡工定 | `#partner/operations` 提交伙伴申请 → 看阶段/阶梯/售卖闸状态 → 看自己的运营待办 |
| 交付者（R3 视角） | 待蔡工定 | `#dispatch/mine` 看收件箱三态分流（临期/待响应/已超时/已处理）→ 对一条测试 offer 走接单或拒单 |
| 平台运营（admin 视角） | 建议蔡工本人 | 后台对申请/线索认领做裁定动作，观察前两方界面回显 |

**观察表字段**（批次三薄切片字段在此激活）：场次编号／走查日期／三方账号（代号）／每步完成秒数／卡点描述／界面困惑点／判停线触发与否／走查结论（通过｜带缺陷通过｜不通过）。

## §3 分步脚本（每步含「预期」与「留痕」）

> 前置：活体 ready 200；三个测试账号已建（viewer/fde_engineer/admin 各一，代号化用户名）；**数据全部用演练造蜂**（`data_origin="drill"` 的包走 E2E 脚本造）。

1. **伙伴申请**：伙伴账号登录网页端（`desktop/web-dist` + 反代）→ 侧栏「伙伴运营」→ 填代号＋区域 → 提交。预期：列表出现「城市观察」阶段行。留痕：申请行 `partner_code`。
2. **阶梯与售卖闸查看**：同页「区域合作阶梯目录」卡。预期：三档目录＋「区域售卖未开放」（闸 closed）。留痕：截图。
3. **我的运营待办**：同页「我的运营待办」卡。预期：只显示本人名下条目（无他人条目、无纪要待办）。留痕：条目数。
4. **派单收件箱三态**：交付者账号 → `#dispatch/mine`。预期：分组「临期待响应／待响应／已超时／已处理」各归其位（演练 offer 建议造一条临期＋一条普通）。留痕：各组条数。
5. **接单动作**：对临期组一条 offer 点「接单」。预期：成功后移入「已处理」（已接单）。留痕：offer_id。
6. **平台裁定回显**：admin 在后台对伙伴申请做阶段动作（既有 admin 面）。预期：伙伴账号刷新后阶段注记更新。留痕：阶段变更时间。
7. **结算可见**：交付者 → `#dispatch/settlements`。预期：接单对应席位行可见（金额按实收口径展示）。留痕：结算行号。

## §4 走查后

- 结论回填观察表 → 交蔡工签字（AI 只整理不代签）。
- 缺陷项按「界面 bug / 口径缺陷 / 服务端缺陷」分类登记 `docs/ecosystem-v1/m3/PROGRESS.md` 待决表（下一轮修复）。
- 本手册不进数据真相层引用（零客户资料；全部演练代号）。

**红线重申**：走查全程零真实发信、零扣费、零签约、零售卖闸开启；客户真实资料永不进系统（红线族条款全程适用）。
