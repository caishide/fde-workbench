# 跨库只读验证脚本（G8，2026-10-30）

把重复的手工跨库核对固化为 `scripts/verify/`： Twenty persons 指标、n8n 最近执行状态与耗时。方法：sql-queries——先探 schema（Twenty 多租户工作区 schema、n8n `execution_entity`/`workflow_entity`）再写查询，全程只读。

## 脚本与约定

| 文件 | 用途 |
|---|---|
| `scripts/verify/run-verify.sh` | 入口：一次跑两个库，输出计数摘要。连接参数全走环境变量（默认值=本机 qiflow compose，容器名/用户/库名，**不含任何口令**——psql 在 db 容器内走本地 socket 免密，脚本也绝不读 .env） |
| `scripts/verify/verify-twenty-persons.sql` | 总数 / 新增窗口（`:window_days`，默认 7）/ ICP 分布 / 去重命中检查 |
| `scripts/verify/verify-n8n-executions.sql` | 最近窗口（`:exec_hours`，默认 24h）工作流×状态计数 + 成功执行耗时（均值/最大，秒） |

只读纪律：每个会话显式 `BEGIN; SET TRANSACTION READ ONLY; … ROLLBACK;`。SQL 一律经 stdin（`psql -f -`）进容器——文件内容不走 Git Bash→WSL→容器 argv，中文不落地被转码。输出只有计数与耗时，**不含客户明细**（符合红线：明细只留在真相层）。

## 口径说明

- **ICP 分布**：管道把每人最高分写进笔记标题「冷邮件草稿 (ICP N)」（`note` ⨝ `noteTarget.targetPersonId`，正则提取取 max）；双层口径 = ≥70 培育 / 55–69 留档 / <55（对应 `QFcommonLeadPipe01` 的两层门禁）。
- **去重命中**：同一主邮箱挂多个未删 person 的邮箱值计数——即跨源按邮箱去重的失效信号，**期望 0**。
- **n8n 版本行**：n8n 同名工作流按版本各占一行，摘要按名称分组可能按版本拆行，属正常粒度。
