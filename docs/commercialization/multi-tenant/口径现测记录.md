## 3. 现测方法附录（可复现）

1. **表/蓝图/路由/迁移**：`cd server && PYTHONPATH=src python scripts/audit/extract_workbench_inventory.py`（官方提取器，输出 448/50/146/58 单头）；表数另有 SQLAlchemy `Base.metadata.tables` 元数据遍历双源互证（脚本遍历全部 44 个域包 `models.py` + `control/chat.py`、`control/lcsc_skills.py` 两个路由内联模型模块）。
2. **全局表分类**：FK 图 BFS（边=表→FK 目标表，排除 `users` 枢纽），可达 `projects` 者为项目域，其余 63 张为全局表；同步记录每表的 subject 列（user_id/created_by/subject_key 等）。
3. **写端点×全局表**：AST 调用图（handler → 递归同模块/跨模块 fde_api 服务函数 → ORM 模型实例化/`update()/delete()/insert()` 类参/`session.add` 实参），write-level＝调用树中出现上述写形态；read-only＝仅 `select/get` 引用。方法学偏差声明：`session.delete(instance)` 数据流不追踪（实例由构造点捕获兜底），模块级注册表派发（如 admin 路由 lambda 表）按函数体逐字面量捕获。**该分析是盘点辅助不是终判，M3b 每端点改造前仍须人工复核归属。**
4. **pytest/mypy**：`pytest --collect-only -q`（本地，2716）；`wc -l server/mypy-baseline.txt`（279）。
5. **Redis 键族**：对 20 个 redis 引用文件逐一提取键模板常量与 f-string 键构造点（清单见盘点表维度 3，含文件:行号）。
6. **非 JWT 面**：官方 route CSV `auth` 列分布（require_auth 377 / require_role 31 / require_minimum_role 8+5 叠加 / require_bridge_token 1 / none-found 26），26 条无装饰器路由逐条读源码定机制。
7. **容量三项**：见《容量实测报告》附录 A（脚本与逐项命令）。
