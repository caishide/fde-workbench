## 维度 2：涉全局表的写端点（逐个：方法 / 路径 / 涉全局表 / 处置建议 / 测试指针）

**方法学**（口径现测记录 §3.3）：AST 调用图逐端点分析，write-level＝调用树出现 ORM 实例化/`update()/delete()/insert()` 类参/`session.add` 实参；read-only＝仅查询引用。排除恒在的 `users`/`refresh_sessions` 身份面接触（每端点经 g.current_user 都「碰」users，不计入）。现测 **write-level 79 + read-only 157 = 236 条**（评估文档先验 122 口径不同源——122 是按域人工判定数，236 是机器保守穷举；M3b 施工以本表为准，宁多勿漏）。

「处置建议」是 M0 的机器判定初始值，**M3b 每端点动工前仍须人工复核归属**（盘点辅助≠终判）。销号时在「销号追踪」节回写 PR 链接。

### 批次建议（M3b 每批 ≤30 端点；「域」= 蓝图粒度，同蓝图端点不得跨批）

四个大组是施工聚簇（按蓝图域归堆）；组内按蓝图打包成 ≤30 端点的实际批次（现测 39 个蓝图，单蓝图最大 20 条，可行）。**同蓝图不得拆到两批**（任务书 §7-M3b）；批间可并行，后合方 rebase 前置。
