## 二、Findings

### F1 [P2] 「origin 永不 push」只有文档约束，无本地强制（已处置）

- **意图原文**：AGENTS.md 红线「`origin` 是上游（gxfde），**永不 push**；工作远端是 `fork`」——违者按事故论。
- **实现现状**：`git remote -v` 显示 `origin` 的 push URL 就是上游地址，且**无任何本地防护**：无 `remote.origin.pushurl` 覆盖、无 `push.default` 约束、无 pre-push 钩子。一行手滑的 `git push origin …` 会直接尝试推上游——唯一拦截是 gxfde 仓库的 GitHub 权限（在仓库控制之外，且本机账号是否持有上游写权限未知）。
- **跨越边界**：是。上游是共享远端，误推会把本地未合并状态/个人分支发布到组织上游，属跨信任边界的事故面。
- **处置（本轮已应用，本机 git config）**：`git remote set-url --push origin FORBIDDEN-origin-is-upstream-use-fork`——push URL 指向非法地址，任何 `git push origin …` 立即以 access-rights 错误失败（已 `--dry-run` 实测拦截）；fetch 不受影响。**每次新克隆须重复此步**（git config 不随仓库分发）。
- **残留风险**：防护是每机一次性的，无法经 PR 强制到其他机器。已建议把该命令写进 README「克隆后初始化」节（见台账十.2，文档变更不属本审计范围擅自改 README 权威）。

### F2 [P3] G4 重写使 4 处意图文档引用漂移（本 PR 修复）

- **意图原文**（自指）：《系统意图-关键流程》步骤 3/4 与《系统意图-自动化面》工具面/输出契约行引用 `guidance/jobs.py:16-66 / 61-81 / 31-46`。
