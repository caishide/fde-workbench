## §0 结论速览

1. **「学案例→能力变强」已有一条完整实证闭环**——诊断报告生成器进化线（案例卡 → 生成 → judge 元验证闸 → 分布读数 → 版本化归因 → 拒因回灌 → 评分曲线），实测生成通过率 0/6 → 3/6 → **6/6**（curve 1→3），且第十七轮用补样推翻过一次单点假信号。**但该闭环目前只覆盖「诊断报告」这一种交付物**。
2. **「交付能力」面上的训练闭环骨架已在**（V3.2 训练场：案例库→沙箱真跑→L-A/L-B/L-C→失败分析→回归盲测），差**三块板**：
   - **缺口一**：知识层案例 → 训练场场景库的**摄取管线**（存储面早已预留，缺转换器与污染边界）；
   - **缺口二**：交付线**可判定读数**（round16 的分布方法论未移植到训练场，单 run 读数会造假信号）；
   - **缺口三**：agent 上下文**知识片段接线**（渲染面已支持，唯一调用点硬编码空元组——管道铺好、水源没接）。
3. 「学习」的形态边界（有意设计，非缺陷）：**进化的是提示词/规则/闸门的版本＋知识条目，不是模型权重微调**；每次进化走人工闸收口、经 N2 归因账本可归因。本文所有方案都在此边界内。

## §2 三缺口多方案设计（推荐前置，否决留痕）

### 2.1 缺口一：案例摄取管线（knowledge/fdeops 案例 → 训练场场景库）

**推荐方案 A′：离线转换器 ＋ 既有 import 路由 ＋ 人工审阅闸**

- NEW `scripts/simulation/import_cases.py`（与既有 `scripts/simulation/acceptance_sweep.py` 同目录）：读真相层案例原件（诊断案例集卡片 / FDE-case-library 抽象重写稿 / fdeops 代号化复盘）→ 产出**场景导入包**（content ＋ reference 两 JSON，落**本地工作目录**，不进仓）→ 蔡工桌面训练场「案例库→导入」人工审阅后走 `import_scenarios`（落库 `source_kind='import'`、`status='draft'`）→ **人工逐字段核对后手动激活**。
- **映射关系（抽象层，非第三方结构化复制）**：
  - 案例卡「客户画像/输入面」→ 场景 `content.visible`（初始简报/已知系统/既定约束）；
  - 案例卡「痛点素材/瑕疵备注」→ `content.hidden.facts`（逐条补披露阶段＋追问线索词，loader 变体机制现成）；
  - 案例卡「判卷基准（问题清单/方案方向/结果口径/人机边界）」→ `reference`（识别必达/产出必达/禁止项/预期结果，rubric 版本随行）。
  - 键名面天然隔离：场景库用训练场自有键名（must_identify 族），与诊断卡键名不同名；转换器在 `scripts/`（钉扫描面外），**repo 被扫面零答案材料不变**。
- **污染单向阀（本稿核心裁定，待拍板确认）**：诊断评测集六卡的判卷基准**允许**进训练场 DB 的 judge 参考面（训练场 judge ≠ 诊断生成器；泄漏自检在位；且 L-B 模型评估的参考材料注入是训练场既有形态）——但**禁止任何从训练场 reference 流向诊断生成器提示词/few-shot 的路径**；实施轮加静态钉（生成器提示词装配面禁止 import simulation 包）机械承载。
- **人工闸保留**：H1–H13 不动——AI 只可起草导入包（可选项，N 线能力复用），审阅与激活恒人工。
- 三方案例逐卡登记 attribution（license / original_url / snapshot_date / rewritten 标记）——诊断卡 attribution 结构直接复用，FDE-case-library 的 MIT 快照日期随卡落档。

**否决方案 B：案例答案直写 repo 种子文件（`simulation/seeds/CASE-*.json`）**——种子目录在污染钉扫描面（`server/seeds` 同族＋`server/src` 内），答案材料进仓直接违红线 R-4；且内部真实案例进 git 违「客户资料不入仓」红线。否决留痕。

**否决方案 C：宿主通道把 knowledge/ 挂进沙箱让 zcode 自读**——违宿主通道边界①「绝不挂真相层」（AGENTS 红线 2026-11-07 裁定）；且未经脱敏审计的原文进模型上下文不可控。否决留痕。

### 2.2 缺口二：交付线可判定读数（round16 方法论移植训练场）

**推荐方案 A：复用 `scripts/diagnostic_eval/eval_lib.py` 分布原语**

- **轴定义**：逐场景按（scenario_version × rubric_version × adapter_mode）分组；**锚点场景**（固定输入＋固定 agent 配置）按（rubric_version × 评估器版本）分组——锚点 run 得分＝纯评估侧噪声，与被测能力无关。
- **判定规则照搬 `delta-noise-band` 语义**（登记新规则号，非校准阈值）：Δ 可判定 ⇔ 两组样本各 ≥3 ∧ |Δ| > 噪声带（严格大于）；n 不足 ⇒ `insufficient_data`（「还没资格判」≠「不可判定」）。
- **预期方差主项在生成端**：L-A 是确定性规则层（同 trace 必同分），run 间方差来自 runner（zcode 行为方差）——与诊断线 round16「生成端方差主导」归因同构；先测锚点（评估侧噪声上界）再读逐场景分布，顺序不可反。
- **底册 CLI** 照 `summarize_distributions.py` 先例：真相层出数字与 run id，仓库侧只存汇总＋指针＋sha256，零报告正文。
- 三条机械不变量照搬：元验证不过的 run 整个不收（训练场对应：泄漏自检失败/适配降级 run 不进分布）；error 行不是 0 分、是无数据；n<2 不编造 stdev。

**否决方案 B：以单 run 的 L-A/L-B 读数直接下「能力变强/变弱」结论**——round16 已实证证伪（judge 噪声 ≥9 分时单点 Δ −6~−7 分全是假信号；第十七轮补样后两个「看着像变差」均复判 `within_noise`）。否决留痕。

### 2.3 缺口三：agent 上下文知识片段接线

**推荐方案 A：静态「经验条目」层起步（seeds 版本化，零检索基建）**

- NEW `server/seeds/lessons.json`：条目＝{id, capability_tags, text, source_ref, sha256}。**内容纪律**：只含抽象打法/判据（来源＝`deliverables/fde-sop-v1.1` 已蒸馏资产＋诊断案例集展示面提炼），**零案例答案、零客户资料、零未溯源数字**；逐条登记 source 指针。
- 接线点＝`agents/service.py:390`：按 agent capability tier＋项目行业 tags 过滤，取 top-K（条数与单条字符上限进配置位，防上下文膨胀）；条目文本走 `render_masked_context` 既有禁区词＋模式遮蔽闸（`context.py` 在位，**零新脱敏面**）。
- 变异验证：M1 摘过滤（任意 capability 全量注入 ⇒ 红转绿）；M2 摘上限（超限注入 ⇒ 红）；M3 条目混入答案字段 ⇒ 静态钉红。

**后置方案 B：检索库/新表（关键词倒排或向量）**——条目量上来后再议，本轮登记不排期。

**否决方案 C：让 zcode 在沙箱内自行检索知识库**——宿主通道无此挂载面；且自检索绕过脱敏闸不可审计。否决留痕。

## §4 与既有排期的关系
