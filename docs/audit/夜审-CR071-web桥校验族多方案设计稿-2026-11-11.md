## 〇、现码状态（现测，两桥校验面对照）

**桌面 IPC 桥**（`desktop/src/main/api-ipc.ts::validateRequest`，强）＝校验族 8 项全在位：
| # | 校验项 | 桌面 api-ipc.ts 锚点 |
|---|---|---|
| 1 | **method 白名单**（GET/POST/PUT/PATCH/DELETE） | `ALLOWED_METHODS` 集合 + `!ALLOWED_METHODS.has(...)` 拒 |
| 2 | **auth 路径排除**（`/api/v1/auth/*` 除 verify-password 不走通用桥） | `isPasswordVerification` 分支 + auth 正则 400 |
| 3 | **编码结构逃逸**（`%252f/%253f/%2523/%255c` 双重编码＋`%2e` 遍历） | `hasEncodedStructuralEscape` |
| 4 | **路径遍历**（raw＋decoded 双查 `..`/`//`/`\`） | `PATH_TRAVERSAL` + `decodedPathname` 系列断言 |
| 5 | **控制字符**（`\u0000-\u001f\u007f` raw＋decoded） | `CONTROL_CHARACTERS` 双查 |
| 6 | **multipart 严格 schema**（非法形状直接拒，非降级） | `validateMultipartFileBody`（exact keys/字段名/100MB/控制字符全钉） |
| 7 | **body 可序列化校验**（`JSON.parse(JSON.stringify)` 回环） | `serializeBody` |
| 8 | **origin 匹配**（finalUrl.origin===apiOrigin） | `new URL(path, apiBaseUrl)/` 归一后断言 |

**web 桥**（`desktop/src/renderer/src/fde-web-bridge.ts::apiRequest`＋`isSafePath`＋`buildMultipartBody`，弱）＝仅 3 项在位：
| 校验项 | web 桥现状 | 缺口 |
|---|---|---|
| **method 白名单** | `options.method` 直传 `fetch`，**零校验** | **缺**——任意 method（OPTIONS/TRACE/自定义）可发 |
| **auth 路径排除** | `isSafePath` 无 auth 分支 | **缺**（同源 web 形态影响面小，但与桌面「auth 不走通用桥」不等价） |
| **编码结构逃逸** | 只 raw `path.includes("..")`，**无 decoded 双查、无 `%25` 双重编码** | **缺**——`%2e%2e`/`%252f` 绕过 raw 检查 |
| **控制字符** | 只查 `\`/`#`，**无 `\u0000-\u001f\u007f` 区间** | **缺** |
| **multipart 静默降级** | `buildMultipartBody` 形状非法 **return null** ⇒ 请求**无 body 裸发**（既不 multipart 也不 json） | **缺**——应拒而非降级（桌面是 strict reject） |
| **origin 匹配** | `url.origin===window.location.origin` | **在位**（web 同源，等价桌面 origin 断言） |
| **body 可序列化** | 直 `JSON.stringify`，无回环校验 | **缺**（web body 为前端自构，风险低，但对齐面缺） |

⇒ 报告一句话「web 桥 apiRequest 校验族系统性弱于桌面 IPC 对应面（method 白名单/auth 排除/编码逃逸/multipart 静默降级）」现测**全部坐实**；
web 桥相对桌面 **7 项缺 6 项**（仅 origin 匹配等价在位）。

## 一、方案对比

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A 规则提升 shared/ 单点（推荐）** | 把 8 项校验抽成 `shared/api-safety.ts` 的**纯函数**（零 electron 导入，tsconfig.node 可测）：`isAllowedMethod`/`isSafeApiPath`（含编码逃逸＋控制字符＋遍历 raw/decoded 双查）/`isAuthExcludedPath`/`validateMultipartFile`（严格 schema，**非法返回错误码而非 null**）/`originMatches`；**桌面 api-ipc.ts 与 web 桥 apiRequest 双消费同一原语**；静态钉＝「两桥对同一组（合法/非法）路径样本判定结果恒一致」＋「web 桥 multipart 非法形状不再降级为无 body 裸发」 | ①**单一权威**＝报告消解条件「规则提升 shared/ 单点」原文；②桌面既有 8 项校验**行为零变化**（只是搬进 shared 再引用，测试全绿兜底）；③web 桥 6 缺口一次补齐且**与桌面恒等价**（静态钉防再漂移）；④纯函数可单测（桌面 `tests/main` 已有 api-ipc 测试面，web 补镜像样本） | ①改动面＝api-ipc.ts（重构引用）＋web 桥（接校验）＋NEW shared 模块＋测试；②desktop 改动⇒便携版重打包 |
| B 双实现各自补齐 | web 桥**独立**复制桌面 8 项校验（不提升 shared） | 不动桌面 api-ipc（零回归面） | **两副本必漂移**（桌面加校验项 web 忘加＝家族性教训「同一坑复发三次」同款）；违背报告「提升 shared/ 单点」原意 |
| C 最小封口（只补 2 项） | web 桥只加 **method 白名单**＋**multipart 严格拒绝**（两项最高危），编码逃逸/控制字符/auth 排除留后续 | 改动最小 | 半吊子：编码逃逸（`%2e%2e`）与控制字符这两项是**真绕过面**（raw 检查可被编码穿透），只封 method/multipart 不解决系统性弱点；下次还得再开一轮 |

**推荐＝A**。实施面清单（实施轮执行，本轮不落码）：
1. NEW `desktop/src/shared/api-safety.ts`（纯函数）：`isAllowedMethod(m)`／`isSafeApiPath(path, {origin})`（内部做 raw＋decoded 双查＋`%25` 逃逸＋控制字符＋遍历）／`isAuthExcludedPath(path, method)`（auth 除 verify-password）／`validateMultipartFileShape(body): ApiErrorDto | null`（严格 schema，**非法返回 error 不返回 null**）／`assertBodySerializable(body)`。
2. `desktop/src/main/api-ipc.ts` 改为引用 shared 原语（行为逐位保留——既有 `ALLOWED_METHODS`/`hasEncodedStructuralEscape`/`PATH_TRAVERSAL`/`CONTROL_CHARACTERS`/`validateMultipartFileBody` 逻辑搬进 shared，主进程侧只做 `throw invalidRequest()` 翻译）。**静态钉＝既有 api-ipc 测试全绿**（行为不变证明）。
3. `desktop/src/renderer/src/fde-web-bridge.ts::apiRequest` 接入：`!isAllowedMethod(options.method)` 拒；`!isSafeApiPath(path,{origin:location.origin})` 拒；`isAuthExcludedPath` 拒；multipart 走 `validateMultipartFileShape` **非法即 `fail({code:"invalid_request"})` 不再裸发**；body 走 `assertBodySerializable`。
4. **等价性静态钉**（关键）：NEW `tests/` 样本集（合法/非法路径 × 桌面/web 两桥消费同一 shared 原语）断言「两桥判定恒同」——防未来任一侧单独加校验项导致漂移。
5. 红线自检：纯桌面安全面，零客户资料/零密钥/零第三方正文；web 形态行为面收窄（原本可发的非法 method/multipart 降级请求被拒）＝**安全收紧非功能放宽**。
