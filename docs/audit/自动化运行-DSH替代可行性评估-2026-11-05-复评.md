## 2. DSH 情况的清晰说明

### 2.1 现状一句话

**DSH 是 V3 已定义但完全未启用的外部编排位：协议面已固化（FDE 自定 `fde-dsh-v1`）、客户端代码已就绪、回调端点已就绪、审批链已就绪，但服务端零部署、配置零填写、适配层零实现、真实业务需求零澄清。**

### 2.2 六个面的精确状态

| 面 | 状态 | 证据 |
|---|---|---|
| **协议定义** | ✅ 已固化 | `config.py:84` `dsh_protocol_version="fde-dsh-v1"`；端点 `/v1/health`、`/v1/executions`、`/v1/executions/{id}/progress`、`/v1/plugins/apply`（`dsh_runtime.py:59-125`、`ai_server_client.py:168`） |

### 2.3 DSH 的真实能力边界（不可替代的部分）

**不是「模型能力」，是「编排协议」。**四项语义只有 DSH 位能承载：

1. **外部执行会话** + `external_execution_id` + `runtime_version`/`agent_profile_version` 随 run 冻结（`automation_task_runs` 落库）。
2. **三类反向回调**：events（进度）/ knowledge（上下文）/ approvals（人工介入请求）。
3. **MCP 回环 token 注入**：`issue_mcp_token` 15min HS256 JWT（claims `sub/ver/project_id/execution_id/capabilities`）注入 `mcp:{url,token}`；`auth_version` 撤销即时失效。
4. **A 轨无人值守执行**：`automation.execute` 唯一执行入口。

### 2.4 DSH 侧现存问题（按严重度）

| # | 问题 | 严重度 | 性质 |
|---|---|---|---|
| 1 | **适配层源码零实现**（协议缺口，非「未安装」） | 高 | 工程缺口 |
| 2 | **A 轨无 fallback**：`automation_jobs.py:90` 直调 DSH，`dsh_not_enabled` → run failed，**无直连降级**（与 B 轨不同） | 高 | 韧性缺口 |
| 3 | **零真实需求澄清**：P3 §4.4-4 与 B#27 均以「用户澄清自动化诉求环节」为触发条件，至今未澄清 | 高 | 决策缺口 |
| 4 | **上游不可信**：developer preview + 未经安全审计 + `sdk-minimal` pins `danger-full-access` + `session-log-deepseek` 默认上传会话日志（≤8MiB/请求） | 高 | 安全缺口 |
| 5 | **运行证据为零**：`automation_approvals=0`/`workflow_runs=0`/`agent_runs=0` ⇒ 任何降级/开放申请缺 §1.5 要素 4 | 中 | 数据缺口 |
| 6 | **官方零命中**：`/v1/executions` 在官方源码中不存在 ⇒ 适配层必须自写全部 REST+回调 | 中 | 工作量事实 |
| 7 | **升级污染溯源**：破坏性变更 + 版本随 run 冻结 ⇒ 回退须连带回退数据副本（FF 语义已抄） | 中 | 运维约束 |
| 8 | **模型合规未定**：境内模型约束未拍板（goal-d14 相关） | 中 | 合规缺口 |

### 2.5 结论

**DSH 当前是「协议已备、运行时零部署、需求零澄清」的悬置状态。**它不是自动化的当前瓶颈，也不是当前可选项——**在需求澄清前启动适配层开发，等于为未定义的需求写代码**，与「不建空壳」纪律相悖。

### 3.3 优先级理由

- **P0 排第一**：§1.5 要素 4（运行证据 ≥N 次零人工否决 + 审批时效 p90 + 零 confirmation 失败锁）是**所有**降级/开放申请的共同前置。**没有运行证据，P1/P2 全部不成立**——这是当前第一约束，做完它才谈得上任何开放。
- **P1 排第二**：G4 是**现役已在事后审计档**的最大一档（37 条），扩容风险最低、收益最直接。
- **P3 值得特别提出**：它是唯一**不依赖运行证据**的自动化提升——纯比对逻辑，且直接缓解「人工阅读复核清单」的负担，同时把人工注意力集中到结论。
- **P4 排在中后**：A 轨降级的**产出形态取决于需求澄清**，需求未定则形态不可定义；先做 P0 顺带产出 A 轨真实诉求数据，再定义降级更稳。
- **P5/P6 明确不排期**：与既有裁决（B#27 §1、借鉴 B#20「当前不装」）一致，避免并行开第二实施线（backlog 头部纪律）。
