## 步骤一 · 在桌面端建试点项目 `pilot-001`

### 1.1 打开「新建项目」

桌面端启动后，左侧菜单找到**「项目」** → 点右上角**「新建项目」**按钮。

> ⚠️ 只有 **admin** 或 **project_lead** 角色能看到这个按钮。如果你看不到，说明当前账号权限不够 ⇒ 换一个 admin 账号登录。

### 1.2 第一屏：选「怎么新建」

会出现三张卡片：

| 卡片 | 说明 | 你选哪个 |
|---|---|---|
| **从模板新建** | 选一个已发布的行业模板，沿用它的模块和任务 | ❌ **别选** |
| **上传预调研表新建** | 上传 DOCX，让 AI 解析生成草稿 | ❌ 不用 |
| **手动新建** | 从空白开始 | ✅ **选这个** |

**为什么别选「从模板新建」**：这条路的系统规则是「选了模板，就必须同时给一个**已发布**的模板版本号」，你现在没有可用的已发布模板 ⇒ 会直接报错 **「The request body is invalid.」**（HTTP 400），白折腾一次。**手动新建**这条路没有这个约束。

### 1.3 第二步：填「基础信息」

界面按顺序有这些框，**带红色星号的是必填**：

| 框 | 填什么 | 必填 |
|---|---|---|
| **项目名称** | `pilot-001` | ✅ |
| **客户名称** | `PILOT`（**代号，不是真名**） | ✅ |
| **所属行业** | 下拉选一个（或选「不选择（可跳过）」） | ⬜ |
| 项目编号 | 留空 | ⬜ |
| openfde engagement（进阶） | **留空** | ⬜ |
| fdeops 工作区（进阶） | **留空** | ⬜ |
| **计划开始日期** | `2026-11-12` | ✅ |
| 计划结束日期 | `2026-11-19`（可留空） | ⬜ |
| 项目背景 | 留空 | ⬜ |
| 备注 | 留空 | ⬜ |

**三个要注意的坑**：

1. **「客户名称」填代号，不要填真名** —— 系统会自动拼出「客户代号」（格式：`客户名称·所属行业`）。这系统里**不存真实客户资料**是硬规矩，填了真名等于违规。
2. **两个「进阶」框留空** —— 那是真相层的工作区路径，**填了会把不该进系统的东西登记进去**。
3. **「客户代号」是自动生成的**，你看不到输入框，也不用管它。

### 1.4 第三步：选「负责人」

下拉框里选**你自己**。如果你就是 `project_lead`，这个框会自动锁定成你本人。

### 1.5 第四步：勾「首期模块」

**至少勾一个**（不勾会报错「请至少选择一个首期模块。」）。

- 候选模块来自「模块目录」，每项前面是个复选框，勾上就行；
- 勾选框旁边的文字是这个模块的名字和「N 项任务」；
- **有依赖关系的模块会自动帮你补勾**（比如勾了 B 但 B 依赖 A，系统自动勾上 A）；
- 想取消某个前置模块会被拦住，提示「该模块是已选模块的前置，不能移除。」——**这是正常保护，不用管**。

> 💡 选哪个模块都行，试点只是跑通流程。选个看着顺手的。

### 1.6 第五步：确认创建

只读摘要页，核对一遍就点创建。

### 1.7 ⭐ 创建成功后那个「另存为模板」弹框

**这是你上次问的那个点**——它**不在表单里**，是**项目创建成功之后**才弹出来的一个询问框：

> **「另存为行业模板草稿」**
> 项目已创建。是否把本次项目配置另存为新的行业模板草稿？
> 按钮：**「另存草稿」** / 「取消」

- 点**「取消」** ⇒ 什么都不做，项目照常建好 ✅（试点阶段你**选这个**）
- 点**「另存草稿」** ⇒ 会再弹一个框让你输「模板名称」，然后把这次的模块/任务配置存成一份可复用的行业模板草稿。

**为什么试点阶段不另存**：模板草稿是给「以后批量开同类项目」用的，试点阶段还没验证过流程，存了反而是给未来埋一份可能不准的基线。

> 💡 **顺带告诉你**：行业模板有独立的管理入口 —— 左侧菜单**「资源」→「行业模板」**（**只有 admin 可见**）。里面能看到所有模板、版本历史，可以「新建模板 / 编辑 / 创建副本 / 停用 / 发布 vN」。**只有「已发布」的版本才能被「新建项目 → 从模板新建」选用** —— 这就是步骤 1.2 里那条路必须先有已发布模板的原因。

## 步骤二 · 配好「凭据槽位」（一条命令）

### 2.1 先搞懂这一步在干嘛（30 秒）

系统里 7 个能跑的智能体，它们去拿 zcode 权限时都指向**同一个槽位**，槽位名叫 `default`。

**这个槽位现在还不存在** ⇒ 槽位不存在 ⇒ 系统会在发起 run 的**第一道门**就拦下来，报：

```
409  agent_unavailable
原因：credential_missing（凭据缺失）
```

**所以这一步就是把这个空槽位建出来。**

> ### ⚠️ 一个反直觉但重要的事实
> 填进去的**内容在当前执行路径下不会被使用**。原因是宿主通道（你 Windows 上的 zcode 代理）对平台凭据**零注入**——它用的是 zcode 自己的登录状态。
> 所以这一步**只需要槽位存在**，**内容填什么不影响能不能跑通**。
> 脚本默认会帮你填一句占位文字，你**什么都不用想**。

### 2.2 ⭐ 你要填的「用户名」和「密码」到底是什么

**这是最容易卡住的一步，先看清楚再动手。**

| 参数 | 填什么 | 说明 |
|---|---|---|
| `--username` | **`admin`** | ⚠️ **不是**「蔡工FDE智能交付系统」——那是**产品名**（软件的标题），**不是账号**。账号名是 `admin`。 |
| `--password` | **你在桌面端能登录成功的那份密码** | 见下面三种情况 |

**密码到底填哪个？三选一**：

| 情况 | 填什么 | 怎么确认 |
|---|---|---|
| **① 你在桌面端已经登录过、且改过密码** | **你改后的那个密码**（就是你现在能在桌面端登录成功的那份） | 打开桌面端，用这个账号密码登录 ⇒ 能进就说明对 |
| **② 你从没改过密码** | `ChangeMe123!` | README「初始化」节的初始值。**首次登录会强制你改密** |
| **③ 你不记得了** | 见下方「密码忘了怎么办」 | |

> 💡 **最稳的做法**：先把桌面端打开，用你记得的账号密码登录一次。**能登录成功 ⇒ 那份密码就是这里要填的密码**。这一条能解决 99% 的情况。
>
> ⚠️ **别反复试错**：登录连续失败 5 次会**锁定约 15 分钟**（README 说明）。

**为什么必须是 admin（或同等的平台身份）**：

写凭据这个操作需要「平台管理员」权限，判定是**两个条件同时成立**：

1. **平台身份**＝账号没有挂在任何企业下面（`org_id` 是空的）；
2. **system_operator 权限档**＝管理员级别的 AI 操作权限。

`admin` 这个角色**天然同时满足**这两条（`server/src/fde_api/control/access.py:102` ＋ `server/src/fde_api/orgs/isolation.py:36`）。别的账号即使被显式授予了管理员档，只要挂在某个企业下面（企业身份），也会被 403 挡下。

#### 密码忘了怎么办（三种办法，从省事到彻底）

**办法 A：桌面端重置（推荐）**

1. 打开桌面端，点登录页的**「忘记密码」**（如果有这个入口）；
2. 或者直接在**服务器数据库**里重置——**告诉 Agent 就行**，一句话的事。

**办法 B：让 Agent 帮你重置（最快）**

跟 Agent 说：「把 admin 的密码重置成 `ChangeMe123!`」，Agent 会在服务器上执行改密（**这是本机开发库的操作，不碰生产**）。

**办法 C：用别的平台身份账号**

库里可能还有别的 admin 账号（比如 `pilot.reviewer`、`gui.regression`）。如果你知道其中某个的密码，可以用它。

### 2.3 执行命令

打开终端：

- **Windows**：按 `Win` 键，搜「**PowerShell**」或「**命令提示符**」，点开；
- 看到黑底（或蓝底）带光标的窗口就是终端。

> ⚠️ **PowerShell 和 Git Bash 的语法不一样**——这是最常见的报错来源。下面三种写法**任选一条**，按你打开的终端选。

#### 写法 ①（最省事，PowerShell / 命令提示符 / Git Bash 都能用）⭐

**不需要 `cd`，不需要设 `PYTHONPATH`**——脚本会自己找 server 的 Python 环境：

```powershell
python D:/test/fde-workbench/scripts/agents/set-credential.py --username admin --password "你的密码"
```

> 💡 如果 `python` 命令不认识，用这个（更保险）：
> ```powershell
> D:\test\fde-workbench\server\.venv\Scripts\python.exe D:\test\fde-workbench\scripts\agents\set-credential.py --username admin --password "你的密码"
> ```

#### 写法 ②（PowerShell 专用）

```powershell
cd D:\test\fde-workbench\server
$env:PYTHONPATH="src"
.\.venv\Scripts\python.exe ..\scripts\agents\set-credential.py --username admin --password "你的密码"
```

> ⚠️ **注意**：`PYTHONPATH=src`（等号写在前面）是 **Git Bash 的写法**，PowerShell **不认**，
> 会报「无法将『PYTHONPATH=src』项识别为 cmdlet」。PowerShell 要写 `$env:PYTHONPATH="src"`。

#### 写法 ③（Git Bash 专用）

```bash
cd D:/test/fde-workbench/server
PYTHONPATH=src .venv/Scripts/python.exe ../scripts/agents/set-credential.py --username admin --password "你的密码"
```

### 2.4 成功的标志

脚本会打印（**如果先换了 Python 环境，会多两行提示，正常**）：

```
换用 server venv 解释器重跑：D:\test\fde-workbench\server\.venv\Scripts\python.exe
（这样你不需要自己设置 PYTHONPATH）

[1/3] 登录成功，已取 access_token。
[2/3] 凭据已写入：default（明文未回显，符合预期）。
[3/3] 回读校验通过：default → credential_configured=true
```

看到 `[1/3]`、`[2/3]`、`[3/3]` 三行就成功了 ✅。

### 2.5 出错了怎么办

| 屏幕上的错 | 什么意思 | 怎么办 |
|---|---|---|
| `无法将"PYTHONPATH=src"项识别为 cmdlet` | **用了 bash 语法** | 换**写法 ①**（不用设 PYTHONPATH） |
| `python 不是内部或外部命令` | 系统没装 python | 用**写法 ①** 的第二条（直接写 venv 里的完整路径） |
| `登录失败（HTTP 401）` | **账号或密码不对** | 回到 **2.2**：先在桌面端确认能登录，再回填密码。⚠️ **别连试 5 次**（会锁 15 分钟） |
| `登录失败（HTTP 400）` | 请求被拒 | 脚本已自动带 `device_label`；**若仍报 400 说明服务端版本较旧**，告诉 Agent |
| `写凭据失败（HTTP 403）` | **这个账号不是平台身份** | 换一个 `admin` 账号（库里有 `admin` / `pilot.reviewer` / `gui.regression` 等） |
| `连不上服务端` + `服务没起？` | 服务没启动 | 先跑 `cd D:/test/fde-workbench && docker compose up -d` |

### 2.6 怎么确认真的配好了

```bash
curl http://127.0.0.1:8010/api/v1/agents/credentials -H "Authorization: Bearer <token>"
```

会看到：

```json
{"data": [{"id": "...", "name": "default", "credential_configured": true}], "error": null}
```

**`credential_configured: true` 就是配好了。**（看不到明文是**对的**——密文入库，永不回显。）

> 💡 **不用手搓这条 curl**——脚本第 `[3/3]` 步已经自己回读校验过了。

## 步骤三 · 打开宿主通道（改 3 行配置）

### 3.1 要改哪个文件

**文件路径：`D:\test\fde-workbench\server\.env`**

> ⚠️ 这是**服务端**的配置文件（不是仓库根目录的那个 `.env`）。用记事本 / VS Code 打开都行。

### 3.2 改哪三行

在文件末尾**追加**这三行（如果已经有同名行，就改那行的值）：

```
FDE_AGENT_HOST_CHANNEL_ENABLED=1
FDE_AGENT_HOST_ZCODE_BIN=D:/software/zcode/ZCode.exe
FDE_AGENT_HOST_ZCODE_CJS=D:/software/zcode/resources/glm/zcode.cjs
```

> ⚠️⚠️ **最常见的坑：占位文字没换成真路径**
>
> 如果你的 `.env` 里那两行长这样（尖括号包着说明文字）：
> ```
> FDE_AGENT_HOST_ZCODE_BIN=<ZCode.exe 全路径>      ← 错！这是占位文字
> ```
> **它不会报错，但一定跑不通**——系统会找不到程序。要把尖括号里的说明**换成真实路径**。
>
> **本机（蔡工电脑）已确认的真实路径**：
> - `D:/software/zcode/ZCode.exe`
> - `D:/software/zcode/resources/glm/zcode.cjs`
>
> 上面这两行就是本机的正确值，**直接抄**即可（如果你自己的机器上 zcode 不在这个位置，再按下面的方法找）。

**在自己机器上找路径的方法**：

| 变量 | 填什么 | 怎么找 |
|---|---|---|
| `FDE_AGENT_HOST_ZCODE_BIN` | **ZCode.exe 的完整路径** | 打开 zcode 安装目录，找到 `ZCode.exe`，**按住 Shift 右键 → 复制文件地址** |
| `FDE_AGENT_HOST_ZCODE_CJS` | **zcode.cjs 的完整路径** | 一般在 `<安装目录>\resources\glm\zcode.cjs` |

> ⚠️ **路径必须用正斜杠 `/`**（如 `D:/software/zcode/ZCode.exe`），别用反斜杠 —— `.env` 里反斜杠会被当成转义符。

### 3.3 改完必须重启服务（这一步最容易被忘）

改了 `server/` 里的东西，**光重启不够，要重新构建镜像**：

> ⚠️ **先看清你在哪个目录！** 下面命令**要在仓库根目录**（`D:/test/fde-workbench`）跑，**不是** `server` 目录。
> 如果你已经在 `server` 目录里，`cd server` 会报「No such file or directory」（因为里面没有再一个 `server`）。
>
> **认准当前目录**：终端提示符长这样 `P1@P1 MINGW64 /d/test/fde-workbench` ⇒ 就在根目录 ✅；
> 长这样 `P1@P1 MINGW64 /d/test/fde-workbench/server` ⇒ 在 server 目录，**先 `cd ..` 回去**。

```bash
# 在仓库根目录执行
cd D:/test/fde-workbench
docker compose build && docker compose up -d
```

然后把数据库升级到最新（一般已经是最新，跑一下更保险）：

```bash
cd D:/test/fde-workbench/server
docker compose exec -T api alembic upgrade head
```

> 💡 `docker compose build` 会花几分钟（重新烤镜像），这是正常的。
>
> 💡 **如果 `docker` 命令说「不是内部或外部命令」**：你的 docker 装在 WSL 里，在 **Git Bash** 里要用这条：
> ```bash
> wsl -d Ubuntu-24.04 -- bash -c "cd /mnt/d/test/fde-workbench && docker compose build && docker compose up -d"
> ```
> 或者**换 Windows PowerShell** 跑（docker 在那里通常可用）。


### 3.4 确认改成功了

在**仓库根目录**执行：

```bash
docker compose exec -T api printenv FDE_AGENT_HOST_CHANNEL_ENABLED
docker compose exec -T api printenv FDE_AGENT_HOST_ZCODE_BIN
docker compose exec -T api printenv FDE_AGENT_HOST_ZCODE_CJS
```

期望输出（三行，**逐字对照**）：

```
1
D:/software/zcode/ZCode.exe
D:/software/zcode/resources/glm/zcode.cjs
```

> ⚠️ **如果第二、三行输出的是尖括号占位文字**（`<ZCode.exe 全路径>`）⇒ **没改成功**，回去看 3.2。
> ⚠️ `exec` 记得加 `-T`（禁用 TTY 分配）——不加在某些终端下会卡住。
> 💡 Git Bash 里如果 `docker` 找不到，用：`wsl -d Ubuntu-24.04 -- bash -c "cd /mnt/d/test/fde-workbench && docker compose exec -T api printenv FDE_AGENT_HOST_CHANNEL_ENABLED"`

### 3.5 ⚠️ 还有两个「必须先满足」的条件（否则 run 会失败）

这是 2026-11-13 在你本机实测出来的两条硬前提，**不是推测**：

**条件 A：zcode 必须已经登录并选好了模型**

- zcode 自己的登录态是 zcode 用的，**平台凭据不参与**；
- 如果 zcode 没登录过、或者没默认选模型，zcode 会直接报错退出：
  ```
  Select a model before sending a message
  ```
- 修法：**打开 zcode 桌面端，手动登录一次、选一次模型**（选完会写进 `~/.zcode/cli/config.json`）。
- ⚠️ zcode 命令行**没有** `--model` 参数可传，所以「默认模型」必须在界面里选好。

**条件 B：provider 覆盖开关要成对设置**

- 两个环境变量要**一起**设：
  ```
  ZCODE_BUILTIN_PROVIDER_CONFIG_FILE=<指向 provider 配置文件>
  ZCODE_PERSONAL_PROVIDER_CONFIG_FILE=<另一个 provider 配置文件>
  ```
- 两者指向**同一个**已存在的 provider 配置文件也可以（zcode 至少要能找到一个可用的 provider）；
- 设了但文件不存在 ⇒ zcode 报「Bundled 与 Active ZCode Built-in Release 均不可用」并退出；
- ⚠️ **`FDE_CONFIG_DIR` 这个变量没用**（实测设了仍走内置 provider）。

> 💡 **这两条具体怎么配，请让 Agent 帮你做一次**（需要读你本机 `~/.zcode/cli/config.json` 和 zcode 安装目录）。文档里已记下 2026-11-13 的实测样本：`{"providerKey":"builtin:bigmodel-coding-plan","modelId":"GLM-5.3"}`。

## 步骤四 · 发起第一个 run（在 AI 对话里）

### 4.1 为什么不是「点一个按钮」

桌面端**没有**「发起 run」的按钮。智能体页面（`项目 → 智能体` tab）是个**只读监控台**，只看已跑过的记录。

唯一能发起 run 的入口是**在 AI 对话里让助手发起**，然后**你输密码确认**。这是设计上的硬规矩：**AI 不能代你发起 run**（它只能「提议」）。

### 4.2 具体怎么做

**第一步**：打开桌面端的 **AI 对话**（左侧菜单找「AI 对话」/「助手」）。

**第二步**：把下面这句话**原样**发给助手（照抄即可）：

```
请帮我为项目 pilot-001 发起一次「质量守卫」智能体的 run。
项目 ID 请先用接口查出来。幂等键用 pilot-001-first-run-001。
```

**第三步**：助手会返回一条**待确认的操作**，桌面端弹出确认框：

> **「确认 AI 敏感操作」**
> 里面有这次操作的说明（操作名、参数）。
> 下方一个**密码输入框**。
> 两个按钮：**「验证并执行」** / 「取消操作」。

**第四步**：在密码框里**输入你当前账号的密码**，点**「验证并执行」**。

- 密码**只在你和系统之间**走，**不经过模型**（模型看不到密码）；
- 确认窗口 **15 分钟**有效，超时了重新让助手提议一次。

**第五步**：等几秒，看「项目 → 智能体」tab 里多出一条 run 记录。

### 4.3 没弹出确认框？排查表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 助手说「没有权限」 | 你的账号 AI 能力档不够 | 让 admin 给你的账号开 AI 权限（`assistant_read` 起） |
| 助手回了文字但没有操作弹框 | 助手没把它翻译成 run 动作 | 把话改得更直接：「请调用 agents.run_start 接口」 |
| 弹框了但点了报 `credential_missing` | 步骤二没配成功 | 回步骤二重跑 |
| 弹框了但点了报「宿主通道已开启但 zcode 路径未配置」 | 步骤三的路径没配对 | 回步骤三 3.2 核对路径 |
| 弹框了但点了报「尚未配置可直连的模型」 | 桌面端没配 AI 模型 | 先在桌面端「个人与安全中心」配一个模型 |

### 4.4 撞到其他闸时的常见报错

| 报错 | 原因 |
|---|---|
| `409 agent_unavailable` ＋ `credential_missing` | 步骤二没配好 |
| `409 agent_unavailable` ＋ `host_channel_bin_missing` | 步骤三的 zcode 路径没配好 |
| `403 ai_access_insufficient` | 账号 AI 档位不够 |
| `404 project_not_found` | 项目 id 填错，或项目没建成功 |
| `409 t1_gate_open` | 带 `solution_id` 时要过 T1 计划评审门 —— **首个 run 别带 `solution_id`** |
| `409 pilot_run_limit_exceeded` | 试点期 run 配额用完（上限 20 或按拍板的 10） |
| `422 agent_forbidden_terms` | prompt 里命中了脱敏禁区词（真实客户名等） |
