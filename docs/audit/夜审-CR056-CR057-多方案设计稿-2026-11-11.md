## 二、CR-057 现码状态＋技术裁定（现测）

三形态 CSP（`desktop/src/renderer/`）：
| 形态 | 文件 | connect-src | 状态 |
|---|---|---|---|
| 桌面打包 | `index.html:7` | `http://127.0.0.1:8010`（唯一主机白名单） | **问题所在** |
| web 发行 | `web.html:10` | `'self'`（同源 Nginx 反代）＋注释注明生产完整 CSP 由 Nginx 响应头下发（任务书-v2 T2-2） | 正确，无问题 |
| harness dev | `gui-harness/vite.config.ts:37` | `'self' http://127.0.0.1:8010`（构建期正则替换，**已有先例**） | dev-only，无问题 |

**关键裁定（方案 B「运行时下发」技术上不可行的依据）**：浏览器 CSP 规则里 **meta CSP 与响应头 CSP 同时存在时取交集**
（strictest-union 语义）。桌面打包态 `index.html` 内嵌 meta CSP＝打包物固定内容，运行时无法删除 meta 标签，
故 main 侧 `webRequest.onHeadersReceived` 注入/放宽 header **对 meta 已锁死的面无能为力**（只能再收紧）——
报告列的「运行时下发」方案在本形态结构性失效，从选项集剔除（留痕防实施轮误走）。

触发矩阵（为何是「半坏隐蔽态」）：
| 部署形态 | API 面（IPC 桥，main fetch） | 文件二进制面（renderer 直连 signed URL PUT/GET） |
|---|---|---|
| 本地 http://127.0.0.1:8010 | ✓ | ✓（CSP 白名单命中） |
| 远程 https API＋local storage（signed URL 经服务端 302/同源？） | ✓ | **CSP 阻断 ⇒ 上传/下载/预览全静默失败**（fetch 抛 CSP 错误，UI 表现为「加载失败」无归因） |
| 远程 https API＋`storage_backend=oss`（`config.py:33` 一等配置，signed URL 直连 OSS 域） | ✓ | **CSP 阻断且 OSS 域＝部署期值，打包期不可知** |

README 两处（:242/:312）明写「远程部署时打包前改 `build.extraMetadata.fdeApiUrl` 为 HTTPS 地址」＝**远程是文档化一等路径**；
桌面产物 `package.json:54` `fdeApiUrl` 默认回环。⇒ 远程形态今天打包即半坏，且无测试钉（CSP 是 HTML 静态字符串，vitest 零覆盖）。
