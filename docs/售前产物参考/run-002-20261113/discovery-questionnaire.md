## 0. 使用说明

1. **不要从头到尾念。** 先用 §1 挑 P0（阻断级），一次会议只攻 P0；P1/P2 留给书面补充。
2. **每个问题都问「为什么问」。** 「为什么问」一列写明它决定哪个产物——这样人工一眼能判断值不值得占用客户时间。
3. **答不上来不等于无效。** 明确记为「不知道 / 需内部确认」并登记到 `assumptions-and-gaps.md` 的缺口表，比猜一个答案有价值得多。
4. **记录方式。** 「答复来源」列写清出处：会议纪要编号 / 邮件主题 / 文档章节 / 口头转述（需二次确认）。口头转述一律标注「待二次确认」。
5. **敏感信息。** 若答复涉及客户敏感数据、身份信息或商业秘密，只登记**存在性与体量级别**（如「约 10 万条文档，格式为 PDF/Word」），不要把原文粘贴进本文件。

### 优先级定义

| 级别 | 含义 | 处理方式 |
|---|---|---|
| **P0** | 阻断级：不答就无法出方案方向或无法估算 | 必须当面/同步确认，否则不出方案 |
| **P1** | 影响级：影响架构选型、工作量、集成方式 | 书面确认，可迭代两轮 |
| **P2** | 优化级：影响体验与长期演进 | 尽量收集，允许留待二期 |

## 4. 首次澄清会议议程（60 分钟，建议）

| 时段 | 内容 | 对应问题 |
|---|---|---|
| 0–5 min | 开场与边界：本次只澄清、不报价；记录人与来源约定 | — |
| 5–20 min | **业务目标与成功标准**（先谈「为什么」，再谈「做什么」） | A-01 ~ A-05 |
| 20–35 min | **场景与范围**：用一个真实案例把流程走一遍 | B-01 ~ B-05、C-04 |
| 35–50 min | **约束**：数据合规、部署形态、集成系统 | C-01 ~ C-03、D-01 ~ D-03、E-01 ~ E-03 |
| 50–55 min | **决策链与采购**：谁拍板、要过哪些流程、时间点 | G-01、G-02、H-01 |
| 55–60 min | 收尾：复述理解（由人工复述并请对方纠正）、确认下一步与责任人 | — |

**提问技巧（写给主持人）**
- 先问「最近一次发生这个问题是什么时候」，用真实事件替代「你们的需求是……」——后者会得到包装过的答案。
- 每问一个问题，追一句「这个数字/说法从哪来的？」，直接生产 `答复来源`。
- 遇到「这个以后再说」，当场记为**已知未知项**并进缺口表，不要跳过。
- 不要在澄清会上展示方案方向（`solution-directions.md` 暂不对外），避免锚定客户。
