## 2. 方向 A：知识检索增强

**成立前提（全部为「必需」假设）**：A-01、A-03、A-04、A-05、A-08、A-10；A-09 弱相关。

**能力构成（草稿，待架构评审）**
1. 知识接入与治理：文档解析、清洗、去重、版本与责任人元数据。
2. 检索层：按业务语义组织（而非仅按文件），支持权限继承与新鲜度标记。
3. 生成层：以检索结果为唯一依据作答，强制输出引用与「无依据则拒答」。
4. 溯源与反馈：逐句可点回原文；用户反馈进入迭代队列。
5. 评测面：基于权威样本的离线评测集（依赖 A-04）与线上采纳率埋点。

**交付形态**：以嵌入现有入口的辅助模块为主，避免另建门户（B-01、D-01 待确认）。

**主要风险**
- 无权威样本（A-04 不成立）→ 只能主观验收，效果不可证。
- 权限与数据授权未确认（A-03）→ 合规阻断。
- 「检索到了但没用上」→ 需引用溯源与拒答策略强行约束，否则用户不信任。

**PoC 验证要点（若走此方向）**
- 取真实业务问题集（依赖 C-04），指标：人工采纳率、引用可核对率、拒答正确率；
- 对照组：现状人工查资料耗时；
- 门槛由人工与验收人共同设定（数值待填）。

**不适用情形**：问题本质是「流程不存在」或「决策无依据」，或数据不可授权使用。

## 3. 方向 B：流程内嵌辅助

**成立前提**：A-01、A-02、A-04、A-05、A-07、A-08、A-09、A-10；A-03 相关。

**能力构成（草稿）**
1. 场景建模：把一个高频作业拆成「输入 → 步骤 → 校验点 → 输出」。
2. 辅助执行：在步骤处给出建议/草稿，保留人工确认点（依赖 A-07、E-03）。
3. 结构化产出：输出进入下游所需格式，减少搬运。
4. 质量闭环：人工修改量与原因回流，作为迭代信号（比「采纳率」更能指导迭代）。

**交付形态**：嵌入业务系统内的功能位（页面内嵌、插件、侧边助手）。

**主要风险**
- 作业描述不准（A-02 不成立）→ 辅助内容无用。
- 业务方不改变作业习惯 → 采用率低，收益不显性。
- 与既有系统的交互/权限改造被低估 → 集成成本吃掉业务价值（A-06）。

**PoC 验证要点**
- 选 1 个高频场景，影子运行：AI 出稿 → 人工改 → 统计人工改动比例与改动原因；
- 指标：单次作业节省时长比例、首次可用率、返工率；
- 必须设「不使用」的对照组，否则无法区分效果与热情（数值待填）。

**不适用情形**：场景低频、一次性、或价值无法用作业量级放大。

## 4. 方向 C：系统集成与自动化

**成立前提**：A-01、A-02、A-05、A-06、A-07、A-08、A-09、A-10；A-03 相关、A-04 弱相关。

**能力构成（草稿）**
1. 流程编排：以事件/任务触发，串联多个系统动作。
2. 接口与映射：读写接口、字段映射、异常重试与幂等。
3. 自动执行与复核：高风险动作前置人工复核点（E-03）；失败可回滚。
4. 观测：端到端追踪、失败告警、人工接管入口。

**交付形态**：后台服务 + 现有系统连接器，对用户尽量「无感」。

**主要风险**
- 接口不可得或不稳定（A-06 不成立）→ 工作量不可控，是本方向最大的不确定性。
- 自动执行错误扩散（A-07 缺失）→ 事故责任归属不清。
- 收益被归到「IT 效率」而非业务指标 → 难以获得业务方持续支持（A-10）。

**PoC 验证要点**
- 打通 1 条最短闭环链路，端到端跑通并做故障注入；
- 指标：端到端成功一次通过率、人工介入率、单次处理成本；
- 需确认失败时的兜底路径与责任人（待确认）。

**不适用情形**：上游系统无可用接口且无改造预算；或动作不可逆且无复核机制。
