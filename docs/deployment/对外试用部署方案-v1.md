## 0. 一页结论

可以把工作台部署成**一台公网服务器上的单实例**，让少量指定外部人员用桌面客户端登录看脱敏演示数据；但必须满足三条硬前提：

1. **只暴露 443**：API 继续只绑 `127.0.0.1:8010`，由同机 HTTPS 反向代理转发，**绝不把 8010 改成 `0.0.0.0`**。
2. **客户端必须重新打包**：`desktop/package.json` 的 `build.extraMetadata.fdeApiUrl` 默认是 `http://127.0.0.1:8010`，打包态代码强制要求 HTTPS（`desktop/src/main/config.ts:17-64`），不改则客户端直连本机、外部人根本登不进来。
3. **账号只能 admin 手动建**：当前无自助注册（`server/src/fde_api/users/routes.py:50` 挂 `@require_role("admin")`），演示账号一律 `viewer`，临时口令带外传递、首次登录强制改密、到期停用。

> ⚠️ **本方案不是多客户 SaaS**。同一实例内所有账号共享同一数据库与项目域、无租户隔离、无数据库层 RLS。**不同客户不得共用同一实例**；多客户场景须先立项租户模型（演进评估已判「暂缓」）。

---

> ✅ **API 域名最终口径（2026-11-09 `OWNER` 二次拍板 A，撤回同日 D 决策）**：工作台 API 的 origin 为 **`https://app.fde18.com`**；`fde18.com` 根域继续承载营销官网，**完全不动**。
> **撤回依据**：`https://fde18.com` 实测已在跑营销官网（标题「蔡工FDE智能交付系统｜带门禁的企业 AI 落地交付系统」，含 `/services/`、`/method/`、`/blog/` 等页面）。D 方案（根域按路径分流）虽能让客户端拿到合法纯 origin，但需迁官网到 `www`、改根域 server 块、301 承接既有链接、核对非 `/api/` 前缀路径、签发双名证书——**每一条都是与线上官网的直接冲突面**，误配会立即影响官网可达性。A 方案把冲突面归零：只新增一条子域 A 记录 + 一张子域证书，官网的 DNS 记录、Nginx 配置、证书与内容一律不改。
> 桌面端 `resolveApiBaseUrl()` 只收纯 origin（`pathname` 必须为 `/`，`desktop/src/main/config.ts:33-41`），子域名是合法 origin，因此**可以用子域，但不能用带路径的根域地址**。§4 的 Nginx 示例为**新增** `app.fde18.com` server 块，不得修改或覆盖 `fde18.com` 官网现有配置。根域 D 方案转为**回退选项**（仅当未来官网下线/迁移且 `OWNER` 重新拍板时启用），不得在执行中临时切换。

## 2. 拓扑与前置条件

```
外部用户（Windows 桌面客户端，已重打包指向 HTTPS）
        │  HTTPS :443
        ▼
[ 反向代理 Nginx / Caddy，同机 ]  ──► 127.0.0.1:8010 ──► [ api 容器 / Gunicorn ]
                                                              │
                              ┌───────────────────────────────┼────────────────────┐
                              ▼                               ▼                    ▼
                       [ redis 容器 ]                [ worker / scheduler ]   [ PostgreSQL 16 ]
                       （不发布宿主端口）                                     （Docker DNS 别名 twenty-db）
```

前置条件（逐项确认）：

- [ ] 一台 Linux 服务器（Docker + Compose v2），具备固定公网 IP、可解析的域名、可申请/部署 TLS 证书。
- [ ] 防火墙/安全组只放行 **443**（以及申请证书期间的 80）；**8010、5432、6379 一律不对外**。
- [ ] 按 `README.md`「快速搭建 · 路线 A」完成建网、PostgreSQL 16（别名 `twenty-db`）、两份 `.env`、构建启动、迁移与初始化。
- [ ] **演示实例与自用生产库物理分离**：新建独立数据库/独立服务器，不从自用库拷贝业务数据。
- [ ] 试用窗口、账号名单、回收责任人已书面登记（登记在仓库外台账，不进 git）。
- [ ] **同机已有其他生产站点与数据库**（2026-11-09 现测）⇒ 演示实例必须新建**独立数据库 + 独立 external 网络**，严禁复用既有生产库／生产网络（对应任务书 T0-3）。`OWNER` 已拍板「就在该生产多站点机开演示实例」（2026-11-09），故 T0-3 的满足方式为**同机 ＋ 独立数据库实例 ＋ 独立 Docker 网络 ＋ 独立数据卷**，不是独立服务器。

| 变量 | 部署值 | 依据与代价 |

## 4. 反向代理与 HTTPS

同机 Nginx **新增 server 块**示例（子域名 `app.fde18.com`；证书路径为 certbot 默认目录，须按实际签发位置核对）：

> ⚠️ 这是**新增**块，**不得修改、替换或覆盖 `fde18.com` 官网现有的 server 块**（含其 80/443、证书与 `location`）。若官网与 API 不在同一台机器，只需把 `app.fde18.com` 的 DNS A 记录指向 API 服务器；本方案默认同机。

> 🔎 **现场适配（2026-11-09 SSH 现测，已执行）**：目标机是**宝塔面板管理的多站点生产机**，Nginx 主配置 include 的是 `/www/server/panel/vhost/nginx/*.conf`，**不是** `/etc/nginx/sites-enabled/`。① 配置已落到**新建文件** `/www/server/panel/vhost/nginx/app.fde18.com.conf`，**未改** `fde18.com.conf` / `www.fde18.com.conf` / `en.fde18.com.conf`（三份 mtime 保持 2026-11-08 16:44）。② 官网证书由面板管理在 `/www/server/panel/vhost/cert/fde18.com/`，SAN 为 `fde18.com, www.fde18.com, en.fde18.com`（2027-01-21 到期），**不含 `app.fde18.com`**，严禁扩展或重签。③ **已按 `certbot certonly --webroot` 为子域独立签证书**，实际路径正是代码块里的 `/etc/letsencrypt/live/app.fde18.com/`（`CN=app.fde18.com`，2026-11-09～2027-02-07）；与官网证书**完全分离**。renewal 已写 `renew_hook = nginx -s reload`、`certbot.timer` 活跃。④ DNS 的 NS 在阿里云万网（`dns31/32.hichina.com`），A 记录由 `OWNER` 在阿里云控制台添加并现测生效（`app → 141.95.33.198`，TTL 600）。⑤ 配置分两步（先 80 段、签出证书后再追加 443 段），每步 `nginx -t` 通过才 reload；官网 `/`、`/blog/`、`/services/` 改前改后均 200。

```nginx
server {
    listen 80;
    server_name app.fde18.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name app.fde18.com;

    ssl_certificate     /etc/letsencrypt/live/app.fde18.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.fde18.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 100m;   # 工作台上传上限，按现场调整

    location / {
        proxy_pass http://127.0.0.1:8010;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

启用前自检：`nginx -t` → 重载 → `curl -i https://app.fde18.com/api/v1/health/ready`（依赖就绪）与 `/api/v1/health/live`（进程存活）；**同时确认 `https://fde18.com/` 官网首页与一条既有路径（如 `/blog/`）仍返回 200、未被本改动影响**。从公网验证 **8010 不可达**。证书续期纳入定时任务，到期告警有人负责。

## 5. 桌面客户端分发

**2026-11-09 已按本节产出一个可安装的实际包**（见「现场产物」）。推荐做法是**命令行覆盖，不改仓库源码**：`electron-builder --help` 官方示例明确支持 `-c.extraMetadata.foo=bar`，无需改 `desktop/package.json`、无需走 PR 流程。

1. 打包命令（在 `desktop/` 目录）：
   ```bash
   npm run build
   electron-builder --win nsis --x64 \
     -c.extraMetadata.fdeApiUrl=https://app.fde18.com
   ```
   打包态 `resolveApiBaseUrl()` 强制 HTTPS、且只接受纯 origin（无 path/query/凭据），写成 `http://` 或带路径会直接抛错（`desktop/src/main/config.ts:17-64`）。**备用后门**：`desktop/src/main/index.ts:162` 运行时优先读环境变量 `FDE_DESKTOP_API_URL`，可用于临时切换地址或诊断；但外部试用者不会设环境变量，正式包仍须烘入正确值。
2. **隔离目录打包的两个硬前提**（2026-11-09 实测踩坑）：若不在主仓工作区打包、而是从 `git archive` 导出源码到独立目录，必须 ① 把 workspace 根 `package.json` + `package-lock.json` 一并复制到该目录（否则依赖收集退化，`app.asar` 里会 **0 个 `node_modules`**）；② 在 `appDir`（`desktop/`）下可见 `node_modules`（junction 到主树根即可），否则触发 `npm install` 并因 workspace 结构报错 `edgesOut`。两者缺一，产物看似成功但运行时缺依赖。
3. **现场产物（2026-11-09）**：源码取 `fork/main` = `9497b2c`（与服务器同版），隔离目录 `D:/test/fde-demo-build/`；产物 `D:/test/fde-demo-build/release/FDE-Workbench-0.3.0-x64.exe`（NSIS，127 MB / 132,157,519 B），SHA256 `8458c7048df0d3a81f04323240a1f9d198dfb0301e1bf5e1ceaaaa6517d2e39a`；同目录另有 `win-unpacked/` 便携版。验收：`app.asar` 内 `package.json` 的 `fdeApiUrl = "https://app.fde18.com"`，打进 **179 个顶层依赖**（mermaid / katex / cytoscape / docx-preview 等齐全；react 由 Vite bundle，不在 node_modules 属正常）。
4. **如实告知使用者**：安装包**未做代码签名**（实测 `Get-AuthenticodeSignature` = `NotSigned`）⇒ Windows 会弹 SmartScreen「未知发布者」，须说明「内部试用包，点『更多信息 → 仍要运行』」；且未做发行验收、**无客户端自更新**（`README.md:312`、`使用手册 §13`）。不要宣称正式发行版。
5. 分发走可信渠道（企业微信 / 网盘私有链接，**勿挂公开下载页**），附：登录地址说明、临时账号（与口令**分两条**带外发送）、试用截止日、遇到问题找谁。127 MB 多数邮箱附件放不下，建议私有链接 + SHA256 供校验。
6. 发出前复核：包内 API 地址指 HTTPS 域名（不是 `127.0.0.1`）、服务端 `/ready` 为 200、**外部机器用 `viewer` 账号真正登录一次**。

## 7. 红线与数据边界

- **无租户隔离**：同实例所有账号共享数据库与项目域 ⇒ 不同客户不得共用实例；也不要把演示账号与内部真实项目放在同一实例。
- 客户真实资料永不进 git 历史与远端；仓库与库内只存代号，原件留在本地工作目录。
- `.env` / `server/.env` 永不提交；`FDE_JWT_SECRET` 是本地密钥加密根，备份时单独加密保管。
- 集成桥只读纪律不变；宿主侧执行通道、发信、外呼等外发动作在演示实例一律关闭。
- 日志与截图脱敏：对外演示的截图不得包含真实客户名、真实项目名、令牌、密钥。

## 9. 运维、升级与回退

- **健康检查**：`/api/v1/health/live`、`/api/v1/health/ready`；worker / scheduler 靠 Redis 心跳判活，`docker ps` 显示 Up 不等于在干活（`README.md`「健康检查」）。
- **升级顺序**：改 `server/` 源码或 `.env` → `docker compose build && docker compose up -d` → `docker compose exec api alembic upgrade head` → 重打包客户端（若 API 地址也变了必须改 `fdeApiUrl`）→ 逐个分发。**无自更新**，每个外部用户都要人工换包。
- **备份**：升级前同时备份 PostgreSQL 与文件卷；不得修改已发布迁移，只能新增。
- **回退**：代码镜像、数据库 schema、客户端包三者版本必须一致回退；回退前先恢复备份，再确认 `/ready` 与登录链路。
- **常见故障**：登录转圈／按钮无效先查 `/ready` 与客户端 API 地址；导出类操作卡在「正在后台生成」查 worker 心跳；详见 `使用手册 §14`。

## 10. 当前不具备的能力（不承诺清单）

| 能力 | 现状 | 影响 |
|---|---|---|
| 自助注册 | 不存在，建号 admin-only（`00-baseline-audit.md` §E.2） | 账号必须人工分发 |
| 租户模型 / 数据库层 RLS | 无 tenant 字段、无 RLS | **不同客户不得共用实例** |
| 公网鉴权与签名发行 | 缺（演进评估 `:201`） | 未签名安装包不能当正式发行版宣传 |
