### 3.1 签署操作指引（2026-11-09 补：解决「在哪签／代号是什么」）

「签 G-A」**不是**产品里的按钮、**不是** git 提交、**不是**在对话里打一行字就算数：它指 `OWNER` 本人在**仓库外台账**留下一行签字记录，再于对话里回一行回执通知执行人。三步：

1. **选载体（择一即可）**：① 密码管理器新建「安全笔记」（推荐，跨设备可留痕）；② 本地文件 `D:\test\fde-demo-ledger\三闸签署台账.md`（执行人已备好空模板，**签署栏全空**）；③ 纸质签字拍照。三者留一份，**不进 git／数据库／截图／聊天附件**。
2. **填签署栏**：把附录 A 的 `G-A 签署` 行或附录 B 闸门表填齐「闸名／日期／`OPS`／`OWNER`／结论」。`OPS` 固定填 `OPS`（2026-11-09 `OWNER` 授权指定的执行人代号）；`OWNER` 填**本人认得出的标识**——推荐直接填 `OWNER` 与全文一致，也可填姓名或拼音。**代号只是台账标签，不是系统账号、无需注册、与服务器权限无关**；`HOST` 为分发与反馈登记人，G-A 行不需要。
3. **回执**：对话里回 `G-A 签署：2026-11-09 / OPS=OPS / OWNER=<你的代号> / 结论：放行 T1–T3`。执行人据此开工，但**不代填台账、不代签、不预勾绿**。

> G-A 判据还含 **T0-4**（轮次窗口／客户代号／重置责任人／反馈渠道／预算告警人）与 **T0-5**（`OWNER` + `HOST` 双签承诺）的台账登记，见附录 A。这两项属 `OWNER`／`HOST` 本人动作，执行人不得预勾绿；签 G-A 时须一并确认，否则按 §3「不得边建边补」处理。台账模板已把 2026-11-09 已裁决的建议值列出，供本人核对而非代填。

> **「打勾」操作口径（2026-11-09 23:2x 补，因 `OWNER` 反馈「不知道怎么打勾」）**：台账 T0 区的 `⬜` 是**普通字符、不是可点击控件**，且文档预览面板只读 ⇒ 点它没有反应属正常。三种等效确认方式：① **首选**：`OWNER` 在对话里回一行本人确认原话，执行人把原话＋日期登记进台账「确认沿革」，九格 `⬜` 原样保留不代填；② 本人用记事本／VS Code 打开台账文件把 `⬜` 改成 `✅` 并保存；③ 台账 §1.1 新增的「一行整体确认」栏填写一次，等价替代九格逐项打勾。**三者都属本人动作，执行人只登记、不代勾、不预勾绿**；不得把「不知道怎么打勾」理解为授权执行人代填。
