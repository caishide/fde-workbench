## 0. 一页结论

把工作台从「分发 Windows 安装包」改成**浏览器静态站点**：客户点一条链接即可登录，同源 `/api` 反向代理到 `127.0.0.1:8010`，不装软件、不传文件、不碰 CORS、服务端零改动。账号从 `viewer` 只读改为 **`project_lead` 功能全开**（上传、导出、门禁证据、AI 对话、agent 全部可用）。

为什么可以全开：v1.0 把功能砍光，根因不是「怕客户看」，而是**数据库无 tenant 字段、无 RLS**，客户能写就会改到全局共享表（`users` / `document_templates` / `module_catalog` / `system_configuration` / 技能与扩展目录 / dispatch 报价结算 / simulation 场景），污染其他客户。v2.0 用**一次只服务一个客户 + 每轮结束快照重置**替代租户隔离：同一时刻只有一个客户能写，写坏了下一轮恢复干净基线即可。**降权换成隔离（时间片），权限照常给满。**

## 1. 适用边界与非目标

| 项 | 口径 |
|---|---|
| 适用 | 一台公网服务器、一个演示实例、一次一名外部客户、有明确起止轮次、轮次间强制重置 |
| 使用者 | 外部客户/合作方，可在代号化演示数据上**完整走一遍业务流程** |
| 数据 | 只用代号化演示数据；客户真实资料不进数据库、文件卷、日志、git |
| 非目标① | 多客户并发试用、自助注册、租户模型、按客户数据隔离、配额计费 |
| 非目标② | 承载真实客户生产数据（R6 商用验收缺口未闭合）、对外承诺 SLA |
| 非目标③ | 桌面端的 Electron 专有能力（见 §4）、签名发行版、客户端自更新 |

> ⚠️ 无 tenant/RLS 是代码事实（全仓搜 `tenant|RLS|CREATE POLICY` 零命中，项目可见性靠 `projects/permissions.py:47-55` 应用层过滤），**不是配置可绕过**。要真正多客户并发，须参数化 `compose.yaml`（端口、库名、external 网络名、env 路径均写死）并起多栈，属成体系改造，本方案不做。

## 2. 拓扑

```
外部客户（任意浏览器，零安装）
   │  HTTPS :443  https://app.fde18.com/
   ▼
[ Nginx 同机，新增 app.fde18.com server 块 ]
   ├── location /        → 静态站点 dist/（HTML/JS/CSS，带 CSP 响应头）
   └── location /api/    → proxy_pass http://127.0.0.1:8010（同源，无 CORS）
                              ▼
                        [ api / worker / scheduler / redis ] ── [ 独立 PG 库 + 独立卷 ]
                              │
                        每轮结束：pg_restore 干净基线 + 清卷 + 重建账号
```

继承 v1.0 的现场资产：`/www/server/panel/vhost/nginx/app.fde18.com.conf`（宝塔 vhost 落点）、独立证书 `/etc/letsencrypt/live/app.fde18.com/`（至 2027-02-07）、独立网络 `automation_qiflow-net`、独立 PG 容器 `fde-postgres` 与独立卷。官网三份 conf 不动。

## 3. 前端生产化 PoC 实测（2026-11-09，本方案成立的前提）

隔离目录 `D:/test/fde-web-poc/`（**不碰主仓**）：复制 `desktop/src/renderer` 与 `desktop/src/shared`，新增生产版桥 `src/renderer/src/fde-web-bridge.ts`，`main.tsx` 首行 `import "./fde-web-bridge"`，`index.html` 的 CSP 改 `connect-src 'self'`，`vite.config.ts` 用 `root=src/renderer` + `/api` 代理到 `https://app.fde18.com`。

| 判据 | 实测 |
|---|---|
| `vite build` | **成功**，27.75 s，产出静态 `dist/`（含 mermaid / katex / cytoscape 等 chunk） |
| 页面渲染 | Chromium 打开 `http://127.0.0.1:4173/`，标题「蔡工FDE智能交付系统」，`#root` 有 2 个子节点、登录表单 2 个输入框 |
| `window.fde` 桥 | `auth` / `api` / `bridge` / `app` 四组齐全 |
| 同源 API 链路 | `fetch('/api/v1/health/ready')` → **200** |
| 错误登录探针 | 返回服务端真实信封 `invalid_credentials`（非 `network_error`、非 CORS 失败） |
| 真实账号登录 | `guest02` 登录 **OK**，拿到 access token，`user.displayName` 为 string、`mustChangePassword` 为 boolean |
| 业务 API 链路 | `GET /api/v1/projects` → **403 `password_change_required`**（首登改密闸在 Web 版同样生效） |
| 控制台 | 非预期错误 **0**；3 条预期噪声（错误探针 401、改密闸 403、meta CSP 不支持 `frame-ancestors`） |

> **PoC 结论：`POC_RESULT=PASS`**。renderer 源码零 Electron API 引用，仓库已有 `desktop/gui-harness/` 浏览器原型（13 页 Playwright 截图）作旁证 ⇒ Web 化是**少量适配**，不是重写。

**两处据实纠正上一轮口头方案**：
1. **httpOnly cookie 与「服务端零改动」不能同时成立**——服务端 `/api/v1/auth/refresh` 现在从 JSON body 读 `refresh_token`，改成 cookie 必须动鉴权端点。v2.0 采用 **token 只存模块内存**：不写 `localStorage` / `sessionStorage`，配合严格 CSP 消除 XSS 窃取面；代价是**刷新页面需重新登录**（试用场景可接受）。httpOnly cookie 列 v2.1 增强，须单独走 PR。
2. **CSP 必须由 Nginx HTTP 响应头下发**：实测 `<meta>` 方式下 `frame-ancestors` 被浏览器忽略。`index.html` 的 meta 保留作兜底，生产以响应头为准。

## 5. 权限与 AI 全开

| 项 | v1.0 | v2.0 |
|---|---|---|
| 角色 | `viewer` | **`project_lead`**，`PATCH /api/v1/users/<id>`（`users/routes.py:74-93` 支持改 `role`） |
| AI 档位 | 显式 `disabled` | **`project_manager`**（rank 3）：`DEFAULT_ACCESS_BY_ROLE["project_lead"]` 即此值，可不写 grant；`CAPABILITY_REQUIREMENTS` 中除 `system.*` / `agent.system.tool` 外全部放行（`control/access.py:36-87`） |
| 上传/导出/门禁/AI 对话/agent | 403 | 全部可用（分片上传 `files/routes.py`、导出 `solutions/routes.py`、worker 队列照常） |

**AI 前置（现场核查，2026-11-09）**：服务器 `server/.env` 中 **无任何模型 API Key**（`FDE_DEEPSEEK_API_KEY` / `FDE_KIMI_*_API_KEY` 均未配置）；`FDE_AI_MONTHLY_TOKEN_BUDGET` 默认 **0 = 不限额**，直接开 AI 有费用风险。代码里已有 `AICallAudit` 审计表、`budget_exceeded()` 按 actor 月度 token 闸与 `budget_blocked` 留痕（`ai/auditing.py:46-56,112-130`、`ai/deepseek.py:121-147`）⇒ **不需要新写配额系统**。

配置口径：注入一个**专用、有额度上限**的模型密钥到 `server/.env`，并显式设 `FDE_AI_MONTHLY_TOKEN_BUDGET=<小值>` 与 `FDE_AGENT_MONTHLY_BUDGET=<小值>`（两者 `0` = 不限额；预算按 actor **自然月**累计、全实例单一数值，见 `ai/auditing.py:35-56`）。`compose.yaml:32-33` 是 `env_file`，配置变更只需按 README 让容器**重新创建**即可生效，**无需 `build` 镜像**。**密钥注入属 `OWNER` 授权动作，执行人不代填、不回显、不读值**；另须在模型服务商控制台设硬性额度上限兜底（代码闸只在发起前查已落审计的用量）。未提供密钥期间：仅 AI 生成/对话类功能返回明确错误，**其余功能照常全开**，不得因此回退到整体只读。填写口径见[评估文档 §7](多客户并发工作量评估-v1.md)。

## 6. 单客户独占时间片与快照重置

1. **干净基线**：在权限放开后、第一位客户使用前，`pg_dump -Fc` 生成基线快照，连同两个文件卷的清单与哈希登记在仓库外台账。
2. **一轮一客**：同一时刻只发放 **1 个** `project_lead` 演示账号；轮次起止日、客户代号、责任人登记在仓库外台账。v1.0 的 3 个并发 viewer 与固定窗口 `11-10～11-24` **作废**，按轮次重新登记。
3. **轮次结束重置**：停用并删除该轮账号 → `pg_restore --clean --if-exists` 回基线 → 清空 `fde_storage` / `fde_transcript_drafts` 两卷 → 重建下一位客户的账号与代号化项目 → 复验 `/ready`、登录、项目可见、**全局表（模板／技能／系统配置）已回到基线**。
4. **演练要求**：重置是**对线上演示库的破坏性恢复**，v1.0 T6-7 只在隔离栈验证过备份链（当时两卷 0 文件）⇒ v2.0 必须先在隔离栈用「全局表被改脏 + 卷内有文件」的样本演练一次，再允许对线上执行。

## 7. 分发与账号生命周期

| 阶段 | 动作 |
|---|---|
| 分发 | **一条 HTTPS 链接 + 一次性激活码/临时口令分两条带外发送**；无安装包、无 SHA256 校验说明、无 SmartScreen 告知 |
| 首登 | 强制改密仍然生效（PoC 已验证）；改密后即可完整操作 |

| 回收 | 停用账号 → 快照重置 → 清卷 → 撤销链接访问（或换 token）→ 反馈汇总 |
| 凭据 | 仍只存服务器 `/root/fde-demo-credentials.txt`（600），不进聊天／git／截图 |

> 严禁把真实客户资料导入演示实例；严禁把临时口令写进文档、issue、截图或聊天记录。

## 8. 红线与不承诺清单

- **无租户隔离**：一次只能一个客户；不得让两位客户同时在线，也不得把演示账号与内部真实项目放同一实例。
- 官网零改动、子域独立证书、独立库/网络/卷、桥 503 / SES false / DSH false / sandbox 不启用 —— 全部继承 v1.0，不改。
- `FDE_JWT_SECRET` 是 JWT 与加密根，不轮换、换机原样携带；两份 `.env` 不入 VCS。
- 日志与截图脱敏；对外材料不得含真实客户名、项目名、令牌、密钥。
- **不承诺**：多客户 SaaS、自助注册、签名发行、客户端自更新、刷新页面保持登录、Electron 专有能力、承载真实生产数据。
